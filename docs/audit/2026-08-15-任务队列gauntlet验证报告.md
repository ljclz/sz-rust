## 3. RED（验证测试有效性）

- **N1 测试首次运行即抓到真实缺陷**：双 worker 消费 10 任务 → handler 调用 **20 次**（calls=20≠10），succeeded 却=10 —— 每任务执行 2 次，被并发领取。
- **N2 测试首次运行失败**（succeeded=0）：测试数据租约过期时长错误（-10s < lease 60s），修正为 -61s 后通过（测试缺陷，非代码缺陷）。
- **修复过程**：v1 方案"单条 UPDATE + WHERE status='pending' 乐观锁"在 MySQL 默认 REPEATABLE READ 下**仍重复领取**（semi-consistent read 仅 READ COMMITTED 启用，UPDATE 锁等待后不重新评估 WHERE）。最终修复为事务内 `SELECT ... FOR UPDATE SKIP LOCKED`（`jobs.rs:claim_batch`，MySQL 8.0.1+），与 PostgreSQL 同语义。

## 6. 已知限制（诚实记录）

- **L1 错误分支未覆盖**：jobs.rs 未覆盖行集中于 DB 错误传播分支（`?`/`InvalidRow`/`NoHandler` 等，需故障注入）；覆盖率 75% line 的缺口即此处。对应 `--fail-under-file-lines 75` 阈值。
- **L2 恶意 payload 无独立测试**：`row_to_job` 对非法 JSON 返回 `InvalidRow`（`serde_json::from_str` 错误），payload 由本系统 `enqueue` 写入（内部可信），未做独立注入测试。
- **L3 无持久化迁移版本**：`init_schema()` 幂等建表，无版本化迁移（ADR-036 已记录）。
- **L4 领取方言依赖**：`FOR UPDATE SKIP LOCKED` 需 MySQL 8.0.1+（ADR-036 已更新）。
- **L5 spec approval 未获取**（autonomous run），EVIDENCE 置信度相应降低。
