## 二、主流框架对标分析

### 2.1 sz-rust 独有优势（对比 Axum/Actix/Rocket/Warp）

| 优势 | 证据 |
|------|------|
| **全栈一体化** | 内置 ORM + 模板引擎 + DI 容器 + 插件系统 + 配置管理，主流框架需拼装 5-10 个 crate |
| **企业级中间件** | 14 个内置（熔断/审计/IP 控制/SSO/CSRF/Sanctum），`middleware-facade/src/lib.rs:26-47` |
| **SIMD 路由加速** | SSE2 加速路径解析，`router-facade/src/simd_str.rs:97`，主流框架无此优化 |
| **OpenAPI 自动扫描** | 从路由配置自动生成，`openapi.rs:55`，无需逐个标注 |
| **类型安全 DI 容器** | TypeId + 三种生命周期 + 上下文绑定 + 循环检测，`container/mod.rs:123-156` |
| **插件系统** | 加载/隔离/事件总线/动态热加载，`addons-loader` + `hot_reload.rs` |
| **多租户支持** | TenantContext/TenantAware 自动注入 tenant_id，`multi_tenant.rs` |
| **ThinkPHP 对齐** | 验证器/缓存/会话/i18n/事件系统全对齐，PHP 迁移友好 |
| **编译时 SQL 校验** | `sql_string!`/`query!` 宏，`orm-facade/src/lib.rs:147` |
| **配置热更新** | ConfigWatcher 文件监听自动重载，`config.rs:595` |

### 2.2 sz-rust 劣势/缺失

| 缺失 | 严重度 | 证据 |
|------|--------|------|
| RouterBuilder 缺 patch/head/options 便捷方法 | 中 | `router.rs` 仅 get/post/put/delete/ws |
| 模板 `{include}` 未实现 | 中 | `view.rs:399-412` render_tag 无 include 分支 |
| 非独立路由引擎 | 低 | 完全依赖 axum 0.8 路由匹配 |
| 生态成熟度低 | 中 | crates.io 1.2.0，社区贡献者少 |
| 文档国际化不足 | 低 | 以中文文档为主 |
| 路由分组无链式 API | 低 | `router.rs:240` 注释标明"未来扩展点" |

### 2.3 定位结论

sz-rust 不是 Axum/Actix/Rocket 的替代品，而是**基于 axum 0.8 的全栈业务框架**，定位对标 ThinkPHP 8 / Laravel / Spring Boot。适合从 PHP/Laravel 迁移到 Rust 的团队。

## 四、综合结论

### 4.1 还有没有幻影交付？

**有，但数量有限**：

1. **sz-rust-k8s-operator**（P0）：孤儿 crate，22 个测试但无消费者，无生产入口可达
2. **README.md 文档欠债**（P0-P2）：版本号 v0.7.0 vs 1.2.0、测试数多处不一致
3. **addons-cms/crm**（P2）：框架能力存在但未接线 sz300
4. **sz-rust-marketplace**（已知）：项目自承认虚构

**AI 能力栈非幻影**：3 Provider + Agent + RAG 均有真实 HTTP 实现 + 215 测试 + sz300 生产接线。

### 4.2 还缺失什么功能？

**框架层面**：
- RouterBuilder 缺 patch/head/options 便捷方法
- 模板 `{include}` 包含未实现
- 路由分组无链式 group()/nest() API

**AI 层面**：
- 无专业向量数据库（仅内存/文件）
- 无多模态（vision）
- 无 RAG 重排序/混合检索
- LocalEmbedding 未真正加载模型

### 4.3 对标主流框架优劣势

**优势**：全栈一体化 + 企业级中间件 + SIMD 路由 + DI 容器 + 插件系统 + 多租户 + ThinkPHP 对齐
**劣势**：生态成熟度低 + 文档国际化不足 + 部分便捷 API 缺失

### 4.4 AI 方面进展和优劣势

**进展**：3 Provider 真实 HTTP + ReAct Agent + 行业 RAG 多源融合 + 国产 API 兼容 + 生产接线
**优势**：国产 API 原生支持 + 多租户隔离 + 限流审计一体化 + 故障切换链
**劣势**：向量数据库生态弱 + 无多模态 + Agent citations 未接入 + RAG 缺 reranker
