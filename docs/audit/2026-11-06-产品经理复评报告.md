## 0. 一句话产品定位（复评者提炼）

> **sz-rust 是一个对标 ThinkPHP 8 API 的 Rust Web 框架，正试图从"开发者工具"升级为"AI 原生高代码平台"——让中小企业技术负责人用 AI 构建集成的业务系统；但当前叙事在"框架"与"平台"两层之间摇摆，且产品技术方案与最新架构决策（ADR-043 废除企业版）存在未对齐的矛盾。**

## 3. 竞品对比表

### 3.1 与 SaaS/低代码平台对比（已有文档）

| 维度 | 微盟/有赞（SaaS） | 秒搭（AI 托管） | sz-rust（AI+自部署） |
|------|------------------|----------------|---------------------|
| 数据主权 | 平台控制 | 平台控制 | **用户控制** |
| 定制化 | 低（标准化） | 中（AI 生成） | **高** |
| 运维成本 | 无 | 无 | **极低（热加载）** |
| 技术门槛 | 无 | 无 | **中（需部署）** |
| 合规保障 | 无 | 无 | **22 条铁律** |

> 证据：`platform-comparison-analysis.md:192-201`、`platform-comparison-analysis.md:248-258`

### 3.2 与 Rust 原生框架对比（**文档缺失，复评者补充**）

| 维度 | axum | actix-web | poem | loco | sz-rust |
|------|------|-----------|------|------|---------|
| 定位 | 极简路由库 | 高性能 Actor 框架 | 全功能框架 | Rails-like 全栈 | **对标 TP8 的全功能+AI** |
| 学习曲线 | 低 | 中（Actor 模型） | 中 | 中（Rails 心智） | **中-高（TP8 心智+Rust）** |
| 生态成熟度 | 高（tokio 官方） | 高 | 中 | 低 | **低（新兴）** |
| AI 能力 | 无 | 无 | 无 | 无 | **有（LLM/Agent/RAG/MCP）** |
| 插件机制 | 无 | 无 | 无 | 无 | **有（addons-loader）** |
| 文档质量 | 高 | 高 | 中 | 中 | **中（中文为主，英文不完整）** |
| 生产案例 | 多 | 多 | 少 | 极少 | **仅 sz300（菜市场秤 SaaS）** |

**关键缺口**：`product-technical-plan.md` 与 `platform-comparison-analysis.md` **完全未对比 Rust 原生框架竞品**。对于"TP6 迁移者"这一目标用户，他们若已转 Rust，axum/loco 是更自然的选择；sz-rust 的替代理由需明确。

### 3.3 与 ThinkPHP 6 对比（迁移存量）

| 维度 | ThinkPHP 6 | sz-rust |
|------|-----------|---------|
| ORM 模式 | Active Record | **Data Mapper + Repository**（心智模型差异） |
| API 风格 | `Db::name()->where()->select()` | `repo.find_by(&[WhereCondition::new(...)])` |
| 部署 | PHP 解释执行，零编译 | Rust 编译，10-60s |
| 热加载 | 改文件立即生效 | M2 进程重启+状态迁移 |

> 证据：`thinkphp-api-mapping.md:25-48`（ORM 差异已明确标注）、`critical-analysis.md:121-160`（编译速度对比）

**判断**：TP6→sz-rust 迁移的**心智模型成本**已被识别（`thinkphp-api-mapping.md:25` 有 ⚠️ 警示），但**迁移工具**（`sz-plugin-migration`）在 `product-technical-plan.md:1994-2010` 标为 Phase 2-T2（2-4 个月），尚未启动。

## 5. 产品问题清单（P0/P1/P2）

### P0 问题（阻断产品化）

#### P0-1：产品定位在"框架"与"平台"之间摇摆，且与 ADR-043 未对齐

- **证据**：
  - `README.md:3`："对标 ThinkPHP 8 的 Rust Web 框架"（框架定位）
  - `product-technical-plan.md:35`："AI-native 通用 Rust Web 框架——用低代码的易用性，生成高代码的能力"（平台定位）
  - `comprehensive-conclusion.md:257`："AI 原生高代码平台"（平台定位）
  - `docs/adr/ADR-043-ai时代单一版本合并.md`：废除企业版，单一开源版本
  - `product-technical-plan.md:1737-1868`：仍描述"开源版/企业版 crate 分离设计"（与 ADR-043 矛盾）
- **影响**：外部受众无法一句话理解 sz-rust 是什么；内部决策依据冲突（ADR-043 已合并企业版，但产品方案仍按分离设计规划 Phase 1-T2）
- **建议**：以 ADR-043 为准，重写 `product-technical-plan.md` 第十一章（开源/企业分离）与第十二章 Phase 1-T2；README 头部增加"AI 原生高代码平台"定位句

#### P0-2：PMF 未验证，无外部用户案例

- **证据**：
  - `product-technical-plan.md:2085-2099`：Phase 3-T3"找到 3-5 个真实用户"标为"持续"，但无启动证据
  - `founder-insights-product-direction.md:25-40`：仅创始人自证（29+ 项目）
  - `docs/audit/` 无任何用户访谈/试点报告
- **影响**：所有产品假设（目标用户/痛点/迁移理由）仅创始人自证，无外部验证；商业化决策建立在未验证假设上
- **建议**：立即启动 3-5 个外部用户访谈（菜市场/生鲜行业技术负责人）；用 MVP（当前 sz300 + AI 辅助迁移工具原型）做 1-2 个迁移试点

#### P0-3：Rust 编译速度破坏"即时应用"体验承诺

- **证据**：
  - `product-technical-plan.md:2193-2207`（R1，P0）：Rust 编译 10-60s
  - `critical-analysis.md:121-160`：对比表显示 Rust 冷编译 10-30s vs PHP <1s
  - `product-technical-plan.md:2200-2206`：5 项应对策略（预编译/sccache/增量/WASM/后台编译）均未落地
- **影响**：热加载体验承诺（"AI 生成即生效"）无法兑现；用户等待 30s 看结果体验差
- **建议**：将"预编译插件模板 + 增量编译"列为 Phase 1 P0（当前在 Phase 1 未提及）；管理用户预期（明确告知编译时间，不承诺"即时"）

#### P0-4：路线图与实际进度不同步，P4 标记"已完成"但时间线未到

- **证据**：
  - `product-technical-plan.md:2103`：P4-T1 前端生成"✅ 已完成（2026-08-12，71 测试通过）"
  - `product-technical-plan.md:2116`：P4-T2 工作流引擎"✅ 已完成（2026-08-12，131 测试通过）"
  - `product-technical-plan.md:2101`：Phase 4 时间线"6-12 个月"

- **影响**：路线图可信度受损；外部读者无法判断当前真实进度；文档损坏降低专业感
- **建议**：修复 `product-technical-plan.md:2140` 文档损坏；将 P4 已完成项移出 Phase 4 或重写时间线；与 `implementation-progress.md`（v2.0.0 已合并）对齐
