## 四、性能审计

### 4.1 auth_service block_in_place 反模式（✅ 已修复）

**v1 状态**：`block_in_place` + `block_on` 调用异步 DB 查询，阻塞 tokio worker。
**v2 状态**：重构为全异步 `authenticate_async`，bcrypt 通过 `spawn_blocking` 在专用阻塞线程池执行。

```rust
// v2 — auth_service.rs
pub async fn authenticate_async(username: &str, password: &str) -> Result<String, String> {
    // ✅ 全异步，无 block_in_place
    let mut conn = pool.acquire().await...;
    let rows = conn.query_with_params(sql, &params).await...;

    // ✅ bcrypt CPU 密集型操作通过 spawn_blocking 在阻塞线程池执行
    let password_matches = tokio::task::spawn_blocking(move || {
        bcrypt::verify(&password_owned, &stored_hash_owned).unwrap_or(false)
    }).await...;
}
```

**修复效果**：
- 高并发登录不再阻塞 tokio worker
- `current_thread` runtime 不再 panic
- 4 核服务器可支持 4+ 并发登录（v1 仅支持 4 个即饿死）

### 4.3 Cache::remember 同步阻塞（🟠 中影响 — 未修复）

```rust
// cache.rs:1173
pub fn remember<T, F>(&self, ...) -> Result<T, CacheError> {
    while self.has(&lock_key)? {
        std::thread::sleep(self.remember_lock_poll_interval);  // 🟠 同步 sleep
    }
}
```
