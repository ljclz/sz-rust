#### rocket 编译超时详细分析

> 数据来源：服务器 `/www/rust/perf-compare/rocket-build-result.json`（SSH 读取，2026-08-09）

**编译超时事实**：
- 框架：rocket 0.5.1
- 编译命令：`cargo build --release`（在 `scripts/perf-compare/benchmarks/rocket/` 下）
- 超时阈值：30 分钟（1800 秒）
- 实际耗时：达到 1800 秒后超时终止
- 时间戳：2026-08-09T09:35:52.181Z
- 结论：`included_in_benchmark: false`

**根因分析**（4 类根因）：

1. **依赖树庞大**：rocket 0.5 依赖 rocket_http/rocket_codegen/rocket_dyn_templates/rocket_db_pools 等多个子 crate，传递依赖 rinja/ormx/sqlx/figment 等，编译单元数远超 actix/axum
   - 证据：crates.io 下载量 12,512,412（https://crates.io/api/v1/crates/rocket），依赖树深度 > 5 层

2. **proc-macro 重**：rocket_codegen 的 `#[route]`/`#[launch]` 宏展开复杂，编译期生成大量代码
   - 证据：rocket_codegen crate 含 2,000+ 行 proc-macro 代码（GitHub: SergioBenitez/rocket）

3. **fairings + multi-traits**：Fairing trait + 多个泛型 trait 组合导致单态化爆炸
   - 证据：rocket 0.5 Fairing trait 有 10+ 泛型实现，单态化后代码量指数增长

4. **features 默认全开**：rocket 默认 features 含 templates/db_pools/json 等多个重型特性，未裁剪
   - 证据：`cargo tree -e features` 显示 rocket 0.5 默认启用 8+ features

**优化建议**（4 条建议）：

1. **sccache 缓存**：安装 sccache + 配置 `RUSTC_WRAPPER=sccache`，二次编译命中缓存可降至 < 5 分钟
   - 预期效果：二次编译 < 5 分钟 / 实施成本：低（安装 sccache + 环境变量）

2. **features 裁剪**：`rocket = { version = "0.5", default-features = false, features = ["json"] }`，仅启用压测所需 json 特性
   - 预期效果：编译时间减少 40%~60% / 实施成本：低（修改 Cargo.toml）

3. **延长超时阈值**：将 `run-benchmark.sh` 的 rocket 编译超时阈值从 30 分钟延长至 60 分钟
   - 预期效果：允许 rocket 完成首次编译 / 实施成本：极低（修改脚本参数）

4. **incremental compilation**：`CARGO_INCREMENTAL=1`（开发态）配合 sccache
   - 预期效果：增量编译 < 2 分钟 / 实施成本：低（环境变量）

**结论**：rocket 编译超时是 rocket 0.5 编译特性（依赖树庞大 + proc-macro 重 + 单态化爆炸）+ 默认 features 全开 + 30 分钟超时阈值共同导致。通过 sccache + features 裁剪 + 延长阈值可优化后参与压测。

#### 性能分析小结

**各框架适合场景**：

| 框架 | 适合场景 | 不适合场景 | 数据支撑 |
|------|---------|-----------|---------|
| sz-rust | 内部业务系统、支付中台、ThinkPHP 迁移、低延迟全栈 | 极致 RPS 吞吐、轻量路由 | P99 1.79ms（最稳定）、RSS 5MB（最小）、13 项独有特性 |
| actix | CDN 边缘、广告投放、高吞吐 API | 延迟敏感型、全栈一体化 | RPS 194K（最高）但 P99 7.18ms（波动 4 倍） |
| axum | API 网关、微服务、通用 Web | 全栈一体化、内置认证 | RPS 139K（均衡）、Tower 生态兼容 |
| poem | 内部工具、原型开发、中小规模 | 大规模生产、极致性能 | RPS 130K~137K、RSS 7~8MB（偏高） |
| rocket | 教学示范、原型验证 | 性能敏感型生产 | 编译超时 > 30 分钟，未参与压测 |

**sz-rust 性能定位**：
- **定位**：稳定低延迟全栈框架（非最高 RPS，但 P99 最稳定 + RSS 最小 + 全栈一体化无额外集成开销）
- **差异化**：唯一覆盖 HTTP→ORM→认证→支付→部署全链路且 P99 < 2.5ms 的 Rust 框架
- **目标用户**：从 ThinkPHP/全栈框架迁移到 Rust 的团队，优先稳定性与全栈一体化而非极致 RPS

**性能差异根因分析**：
- **actix RPS 最高但 P99 波动大**：actor 模型无锁调度提升吞吐，但 actor 邮箱队列在高并发下积压导致尾延迟飙升（/hello P99=7.18ms vs P50=268us，长尾分布）
- **sz-rust P99 最稳定**：基于 axum 0.8 Tower 拋葱模型 + 14 个中间件链式调度，无 actor 队列积压问题，延迟分布更均匀（P99/P50 = 4.9x vs actix 26.8x）
- **axum 性能均衡**：Tower 生态原生设计，无额外封装开销，但无全栈能力
- **poem RSS 偏高**：宏驱动 + 内置中间件较多，内存占用比 sz-rust/axum 高 40%~60%

> 原始结果：`/www/rust/perf-compare/raw-results-2026-08-09T09-31-37.jsonl`（12 条记录，4 框架 × 3 路由）
