## 二、成熟度定位

### 2.1 结论

> **代码质量已达到企业级标准（代码层成熟度 ≈ 85/100），但产品成熟度尚处「单业务深度定制框架」阶段（≈ 50/100）。**

定性：这是一个**内部全栈框架**（Rust 版 Laravel/ThinkPHP 形态），围绕鲜视达智能秤生态定制，与 axum 式的通用生态框架不构成直接竞争关系，而是「业务解决方案 + 框架」的复合体。

### 2.2 评分维度

| 维度 | 评分 | 依据 |
|---|---|---|
| 代码质量 | 85/100 | clippy 0 警告 / fmt 0 差异 / 5,302 测试 / 16 门禁 |
| 功能覆盖 | 90/100 | 全栈：ORM+调度+队列+缓存+MCP+热加载+PDF/Excel/二维码 开箱即用 |
| 工程化 | 80/100 | 12 ADR / 12 条铁律 / 9 Skills / 完整部署栈 |
| 性能 | 80/100 | 亚微秒热路径，但缺横向对比 |
| 生产验证 | 20/100 | 无真实流量 / 无长稳报告 / 无故障演练 |
| 发布与生态 | 15/100 | 核心包未发布 crates.io / 外部使用者为 0 / 无跨版本兼容承诺 |
| **综合** | **50/100** | 代码极强，产品化极弱 |

## 四、与同类框架对比

| 维度 | axum | actix-web | sz-rust |
|---|---|---|---|
| 定位 | 通用生态框架 | 通用生态框架 | 业务全栈框架 |
| 代码量 | ~50K LOC | ~80K LOC | 350K LOC（含 ORM） |
| 开箱即用 | 需自行组合 | 需自行组合 | **全栈：ORM+调度+队列+缓存+PDF+Excel+二维码+MCP+热加载** |
| 测试严谨度 | 社区测试 | 社区测试 | 16 门禁 + 5,302 测试（更严） |
| 社区/生态 | 数十万用户 | 数十万用户 | 0（内部） |
| 版本稳定性 | 稳定 | 稳定 | v0.3.0，无承诺 |
| 特定优势 | 类型安全、tokio 官方 | 高吞吐 | **业务插件体系**（智能秤协议栈 sz-protocol **已撤回：目录空，Cargo.toml 无引用**） |

**护城河不在框架通用性，而在业务集成深度**：addons-operate 单包 18K LOC、sz-orm 41 包生态——这些是 axum/actix 给不了的。（注：sz-protocol 智能秤协议栈原列为护城河，实测目录空且 Cargo.toml 无引用，**已撤回该声称**，见 2026-08-04-代码实测深度评测.md:123）

## 六、开发参照基线（每次迭代对照）

1. **门禁不可退**：clippy 0 警告 / fmt 0 差异 / 全量测试 0 失败，是每次提交的底线
2. **实测优先**：任何"能力"声明必须有 `cargo test` / bench / tree 依据，禁止引用历史文档
3. **生产验证节奏**：P0 两项（发布 + 生产验证）完成前，不宣称"可生产"
4. **安全基线**：cargo-audit 告警必须逐条解释（幻影依赖要附 `cargo tree` 证据）
5. **架构纪律**：12 条铁律 + 12 份 ADR 为决策边界，新增能力先写 ADR 再实现
