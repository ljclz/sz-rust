## 一、正确性 ✅

- 原子领取：单条 `UPDATE ... WHERE id IN (SELECT ... LIMIT n)` 抢占 + 按 `locked_until` 精确过滤读回，并发 worker 竞争同一行时 affected_rows 只允许一个成功（`jobs.rs:claim_batch`）。真实 MySQL 下集成测试验证。
- 状态机：pending → running（领取）→ succeeded / pending+run_after（重试）/ dead（超限或 Permanent），状态转换测试覆盖（`test_job_status_transitions`）。
- 退避公式：`base * 2^min(attempts,6)` 封顶 cap，抖动范围单测覆盖（`test_backoff_delay_jitter_range` 50 次采样 4~6s）。
- 幂等：`UNIQUE(kind, dedupe_key)` + `ON DUPLICATE KEY UPDATE id=LAST_INSERT_ID(id)`，真实 MySQL 验证同 key 返回同一 ID 且 pending 不增（`test_enqueue_dedupe`）。
- 验证证据：`cargo test -p sz-rust-orm-facade --lib jobs::` → 6 passed；`cargo test -p sz-rust-sz300 --test jobs_integration_test -- --ignored` → 5 passed（真实 MySQL 9.6 @127.0.0.1:3306）；`cargo test -p sz-rust-sz300` 全量通过（43 lib + 集成全绿）。
- 集成测试并行干扰已处理：共享 sz_jobs 表，测试体加 `TEST_LOCK` 进程级互斥串行化（`jobs_integration_test.rs:15-17`）。

## 二、可读性 ✅

- 模块头注释完整说明设计要点与工程实践对应关系（`jobs.rs:1-24`）。
- 状态/错误分类枚举带语义注释（Temporary=可重试 / Permanent=不可重试）。
- SQL 全部参数化绑定 + 显式列投影，无 `SELECT *`（`claim_batch` 读回列清单）。

## 三、架构 ⚠️

- 落点遵循既有模式：通用能力在 facade 增强层（同 pool_config/pool_scaler），业务接线在 sz300。
- ⚠️ 已知边界：建表 SQL 为 MySQL 方言（sz300 主数据源），PG 支持待后续（领取 SQL 本身方言无关，见 ADR-036 影响段）。
- ⚠️ 已知边界：v1 无正式迁移版本管理，`init_schema()` 幂等建表；生产需版本化迁移时接 sz-orm migration（ADR-036 已注明）。
- 表名固定 `sz_jobs`，多租户/多队列场景未建模（后续可按需加 namespace 列）。

## 四、安全性 ✅

- 全部 SQL 经 `execute_with_params` / `query_with_params` 参数化绑定（铁律：WHERE 必须参数化），无字符串拼接注入面；表名/状态值为编译期常量，非用户输入。
- 无新增 unsafe（`#![forbid(unsafe_code)]` 编译通过）。
- 错误信息（last_error）仅记录任务失败原因，不承载敏感业务数据；队列快照只输出聚合计数。

## 五、性能 ✅

- 领取为单条 UPDATE + 一次 SELECT（每轮 batch_size 上限 10），worker 空转轮询间隔 1s，DB 开销可忽略。
- 原子计数器与索引：`idx_sz_jobs_status_run_after (status, run_after)` 覆盖领取查询路径。
- ⚠️ 注意：worker 单线程顺序处理批次（简单可靠优先）；高吞吐场景可横向加 worker 实例（原子领取天然支持多实例），或后续加每实例多任务并发处理。

## 结论

5 个维度均无阻断项（❌ 0 项），本次变更可合入。遗留边界（PG 方言、迁移版本化、多租户）已在架构维度标注为已知取舍，跟踪见 ADR-036。
