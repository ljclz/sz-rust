## 2. 本会话修改明细

### 2.1 插件真实验签（AppSec P0-1）

**问题**：`plugin_manager.rs` 的 `verify_signature` 只检查 `signature.len() >= 64`（伪验签），`ed25519-dalek` 已在 workspace 依赖却未接线。

**修改**：
- `packages/sz-rust-sz300/Cargo.toml`：新增 `ed25519-dalek.workspace = true`。
- `packages/sz-rust-sz300/src/services/plugin_manager.rs`：
  - 新增 `base64` / `ed25519_dalek::{Signature, Verifier, VerifyingKey}` 导入。
  - `verify_signature` 重写为：Base64 解码公钥（32 字节）→ 解码签名（64 字节）→ 解码插件包内容 → `VerifyingKey::verify(package, &signature)`；任一失败 fail-closed。
  - 测试模块：`make_plugin` 改用真实私钥对 package 内容签名；新增 `test_install_forged_64byte_signature_rejected`（伪造 64 字节签名被拒）与 `test_install_invalid_public_key_rejected`（无效公钥被拒）。

**验证**：`cargo test -p sz-rust-sz300 --lib`（见 §4）。

### 2.2 测试夹具对齐生产 DDL（数据层 D1/D4 跟进）

**问题**：`tests/common/mod.rs:192` 的测试 merchant 表自造 `merchant_name` 列，而生产 DDL `migrations/001_init.sql:20` 列名为 `name`——服务层改为 `name AS merchant_name` 后测试库将报 `Unknown column 'name'`。

**修改**：
- `tests/common/mod.rs` `setup_merchant_table`：`merchant_name` → `name`，并补齐 `market_id / stall_no / category / bank_account / bank_name / created_at / updated_at` 生产列。
- `tests/common/fixtures.rs` `insert_merchant`：`merchant_name` → `name`。

### 2.3 sz300 纳入覆盖率矩阵（Phase 0-3）

**问题**：`coverage.yml` 仅有 P0-P4 分片，`sz300` 主业务应用不在矩阵（SDET P1-1 残留）。

**修改**：
- `.github/workflows/coverage.yml`：P4 分片 `cargo llvm-cov` 命令追加 `-p sz-rust-sz300`。
- `docs/audit/coverage-exemption.md`：登记 `sz-rust-sz300` 豁免（首次纳入矩阵，87+26 lib 测试全绿但生产路径覆盖待补齐，2027-01-28 复审）。

### 2.4 幻影依赖清理（Phase 0-4）

**问题**：`rkyv`/`zerocopy` 在 `sz-rust-zerocopy/src/serializer.rs` 仅出现在注释与零大小占位结构体，从未真正调用（实际序列化走 serde_json）。

**修改**：
- `Cargo.toml`（workspace）：删除 `rkyv = "0.8"` 与 `zerocopy = "0.8"`。
- `packages/sz-rust-zerocopy/Cargo.toml`：删除 `rkyv = { workspace = true }` 与 `zerocopy = { workspace = true }`。

**验证**：`cargo check -p sz-rust-zerocopy` = 0 error（见 §4）。
