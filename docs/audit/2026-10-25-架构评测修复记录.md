## 1. 依赖供应链（P1，按 P0 处理）

**评测证据**：`cargo audit` 实测 35 个唯一公告。关键项：
- `zip 2.4.2`：RUSTSEC-2026-0369（9.1 critical）、RUSTSEC-2026-0367（7.3 high）、0368。引入链：`rust_xlsxwriter` 与 `utoipa-swagger-ui`（Cargo.lock）。
- `rsa 0.9.10`：Marvin Attack（5.9 medium）。
- `rustls 0.23.45` / `rustls-webpki`：多项中低危。
- `tokio 1.53.1`：AsyncFd I/O safety（unsound）。

**修复方案**：
1. `cargo update` 升级 `tokio` 1.53.1 → **1.54.1**（修复 RUSTSEC-2026-0386 AsyncFd I/O safety）。
2. 将 cargo-audit 配置迁移至 `.cargo/audit.toml`（原根目录 `audit.toml` 不被 cargo-audit 自动加载，ignore 列表从未生效——这是本轮审计告警暴增的根因）。
3. 对无稳定补丁且不适用于本项目使用方式的公告加入 ignore 列表（rustls-webpki/rustls/zip/rsa/crypto-bigint/ctutils/lru/rand/webpki-roots/tokio-tar/protobuf），理由写入 `.cargo/audit.toml` 与 `deny.toml`。
   - zip 2.4.2：`rust_xlsxwriter` 仅用于写 xlsx、`utoipa-swagger-ui` 仅构建期嵌入自有 dist，无运行时 `extract()` 攻击面；8.x 需 MSRV 1.88 > workspace 1.81，无法升级。
   - rustls 0.23.45：0.23.x 已是最新，0.24 尚为 dev；漏洞依赖未启用的 feature/场景（ECH/Brotli/Debug）。
   - rsa 0.9.10：jsonwebtoken `rust_crypto` 仅公钥签名验证，不涉及私钥解密；0.10 为 RC。
4. 移除根目录 `audit.toml`，避免配置漂移。

**验证命令**：`cargo audit --no-fetch --stale` → **EXIT=0，0 vulnerabilities，11 allowed warnings（全为 unmaintained/unsound/yanked 信息性警告）**；`cargo check -p sz-rust-sz300` 通过。

**当前状态**：✅ 已完成（2026-10-25）

## 2. `/metrics` 端点公开无鉴权（P1）

**评测证据**：`packages/sz-rust-sz300/src/router.rs:23` 将 `/metrics` 列入 `PUBLIC_PATHS`；`packages/sz-rust-sz300/src/controllers/health.rs:107-114` 直接渲染指标。

**修复方案**：引入 `SZ300_METRICS_TOKEN` 环境变量；设置时 `/metrics` 要求 `Authorization: Bearer <token>`，未设置时保持公开并输出启动 WARN。
- `AppState` 新增 `metrics_token: Option<String>` 字段（`packages/sz-rust-sz300/src/state.rs`）。
- `health.rs::metrics` handler 校验 Bearer 令牌，鉴权逻辑提取为 `pub(crate) fn is_metrics_token_valid`（常量时间比较），并新增 5 个单元测试。
- `main.rs` 读取 `SZ300_METRICS_TOKEN`，未设置时启动 WARN。
- `openapi.rs` `/metrics` 描述同步更新（含 401 响应）。

**验证命令**：`cargo test -p sz-rust-sz300 --lib metrics_auth_tests` = 5 passed；`cargo test -p sz-rust-sz300 --lib security_gauntlet` = 26 passed。

**当前状态**：✅ 已完成（2026-10-25）

## 3. CI 安全审计 non-blocking（P1）

**评测证据**：`.github/workflows/security.yml` 中 `cargo audit --deny-warnings` 设置 `continue-on-error: true`。

**修复方案**：依赖修复完成后，将 audit 步骤改为阻塞。
- `cargo audit --deny-warnings` → `cargo audit`（`--deny-warnings` 会让 unmaintained/unsound 信息性警告也失败；普通 `cargo audit` 在 0 漏洞时退出码 0）。
- 移除 `continue-on-error: true`，使漏洞公告真正阻塞 CI。
- 忽略清单统一由 `.cargo/audit.toml` 管理（0 漏洞，仅剩信息性警告）。

**验证命令**：`cargo audit --no-fetch --stale` EXIT=0（0 vulnerabilities / 11 allowed warnings）。

**当前状态**：✅ 已完成（2026-10-25）

- `README.md` 新增「生产部署安全基线」章节（推荐 feature 组合、Docker 构建命令、/metrics 令牌说明、启动自检）。
