### 2.3 P0-NEW 失败测试核验

| 核验项 | 结果 |
|--------|------|
| vectorize.rs:474 测试代码存在 | ✅ `assert_eq!(second.success, 0)` 真实存在于 `packages/sz-rust-rag/src/vectorize.rs:474` |
| 测试函数名 | ✅ `cold_start_with_existing_journal_skips`（vectorize.rs:444） |
| 报告作者日志含 FAILED | ✅ `.rerun-sdet-2026-11-06-workspace.log:10145` `test vectorize::tests::cold_start_with_existing_journal_skips ... FAILED` |
| 日志含 panic 位置 | ✅ line 10151 `panicked at packages\sz-rust-rag\src\vectorize.rs:474:9` |
| 日志含 assert 详情 | ✅ line 10152-10154 `assertion left == right failed: left: 1, right: 0` |
| **独立复现失败** | ❌ **无法复现**：`cargo test -p sz-rust-rag --lib cold_start_with_existing_journal_skips` → `1 passed; 0 failed`（17.34s） |
| **独立复现全量 sz-rust-rag** | ❌ **无法复现**：`cargo test -p sz-rust-rag --lib` → `104 passed; 0 failed; 0 ignored`（19.93s），报告声称 `103 passed; 1 failed` |

**P0-NEW 根因分析**：
- 测试逻辑（vectorize.rs:444-475）：创建临时 journal，第一次 cold_start 扫描仓库根目录所有 .rs 文件并 vectorize，第二次 cold_start 应跳过已 vectorize 文件（期望 second.success == 0）。
- `workspace = Path::new(env!("CARGO_MANIFEST_DIR")).parent().parent()` 即**仓库根目录**——测试依赖全局 workspace 文件状态。
- **workspace 全量跑时**：其他 crate 的测试可能触发 cargo 重新编译、生成临时文件、或修改 .rs 文件 mtime，导致第二次 cold_start 时 journal 记录与实际文件 mtime 不一致，second.success == 1（有 1 个文件被重新 vectorize）。
- **单独跑 sz-rust-rag 时**：无其他测试干扰，文件 mtime 稳定，second.success == 0 通过。
- **结论**：这是**典型的 flaky test（测试隔离缺陷）**，非稳定代码回归。报告定性为 P0「发布阻塞项」**过重**——CI 中 nextest --retries 2 会重试，且独立跑通过。
