### P1-1 native 插件热加载无完整性校验

| 字段 | 内容 |
|---|---|
| **当前现状** | `packages/sz-rust-core/src/runtime/hot_reload.rs:347` `let library = unsafe { Library::new(&path) }?;` 直接 dlopen 加载 `addons/` 下 `.dll/.so/.dylib`，**无签名/哈希/白名单校验**（grep `verify\|hash\|sha256\|whitelist` 在该文件无匹配）。`load_and_init_blocking`（:343-365）仅做 dlopen → dlsym(`addon_init`) → catch_unwind 调用，无完整性校验步骤。 |
| **feature 默认状态** | `packages/sz-rust-sz300/Cargo.toml:112` `hot-reload = ["sz-rust-core/hot-reload"]`，**不在 default 列表**（:100-109 default 含 6 安全 feature 但不含 hot-reload）。`main.rs:66-114` 用 `#[cfg(feature = "hot-reload")]` 条件编译，默认关闭时仅打印"Addon 热加载未启用"日志。 |
| **修复方案** | **方案 A（推荐）：SHA-256 白名单校验**。①在 `hot_reload.rs` 新增 `AddonTrustStore` 结构体，从 `addons_trust.toml`（或环境变量 `SZ300_ADDON_TRUST_MANIFEST`）加载 `{ "liboperate.so": "sha256:abc...", ... }` 白名单；②在 `load_and_init_blocking`（:343）入口处、`Library::new`（:347）之前插入 `verify_integrity(path)` 步骤：用 `sha2::Sha256`（workspace 已有依赖，`sz300/Cargo.toml:61`）算文件 SHA-256，比对白名单，不匹配 `return Err(HotReloadError::IntegrityCheckFailed)`；③新增 `HotReloadError::IntegrityCheckFailed` 变体；④fail-closed：白名单未配置时拒绝加载（除非显式 `SZ300_ADDON_TRUST_PERMIT_UNKNOWN=true`）。<br>**方案 B：目录权限审计 + 启动时完整性记录**。不改加载逻辑，仅在启动时算 `addons/` 下所有 .dll/.so/.dylib 的 SHA-256 写日志/审计链，要求 `addons/` 目录仅 root 可写（`chmod 700 addons && chown root:root addons`）。<br>**方案 C：禁用热加载**。保持 feature 默认关，加 CI lint 禁止 `hot-reload` feature 出现在生产构建参数（`Dockerfile` `SZ300_FEATURES` + `docker-compose.prod.yml`），README 明确禁止生产启用。 |
| **是否需用户决策** | **是** |
| **决策点描述** | 是否在生产启用 native 插件热加载？如启用 → 选方案 A 或 B（A 更强，B 更轻）；如不启用 → 选方案 C（仅需文档 + CI lint）。决策依据：是否有运行时动态安装插件需求（多租户插件市场 / 热更新）。 |
| **工作量估算** | 方案 A：1-2 人日（加 `AddonTrustStore` + `verify_integrity` + 白名单加载 + fail-closed 测试 + 负例测试）；方案 B：0.5 人日（启动时算 hash 写审计 + 文档）；方案 C：0.5 人日（CI lint + 文档）。 |
| **优先级建议** | P1（应该修）。当前 feature 默认关已缓解，但若生产启用则是任意代码执行面。 |
