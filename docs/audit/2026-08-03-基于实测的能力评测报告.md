## 2. 编译性能实测 🟢

| 指标 | 实测值 | 命令 |
|------|--------|------|
| 全量 debug 测试构建+运行 | ~4m52s（首次 clean 后） | `cargo test --workspace --jobs 1` |
| 独立编译总基线（check 9 关键 crate） | 27.61s | `scripts/check-compile-time.sh` |
| 单 crate check（http-facade） | 9.77s | 同上 |
| 全量 release 构建 | **25m 17s**（lto=fat + codegen-units=1，26 包） | `cargo build --release --workspace` |

> **B2 编译优化评估（2026-08-03）**：release 25m17s 中 lto=fat + codegen-units=1 是主因（二进制最小、性能最优）。可选 `lto=thin`（预计编译时间 -30~50%，二进制略大，运行时性能损失 <2%）或 `codegen-units=4`（编译更快但优化降低）。**结论：保持 lto=fat**——发布频率低（版本发布才全量 release），编译时间为一次性成本；本地开发用 debug profile（增量 0.2~3s/crate）不受影响。若未来 CI 需要频繁 release 构建，再评估 thin。
| 增量编译（缓存命中） | 0.2~3s / crate | 脚本对比模式 |

**实测平台限制**：Cargo 并发编译存在 crate 解析竞争（E0463/E0460），必须 `--jobs 1`——这是本机多次实测复现的稳定现象（CI 注释中亦有记载）。

## 11. 结论（事实清单）

**达标（实测证明）**：
1. 4,994 测试 0 失败；fmt/clippy/doc 三门禁全绿（修复后）
2. 路由/DI/JSON 热路径亚微秒级；RSS 3.86 MiB 启动、无泄漏迹象
3. unsafe 收敛于 3 处 FFI；脱敏/路径防护/SQL 参数化均有测试与工具实测
4. 模块化 26 包，依赖方向无环（P3 实测编译通过 + 集成测试）

**A~D 级优化执行结果（2026-08-03 追加）**：
- **A1 铁律 2**：权威扫描（排除测试/字符串/注释/示例）生产 unwrap = **0 处**（622 为正则误报已修正）；工具固化 `scripts/check-unwrap.py` 可作门禁
- **A2 env 竞态**：4 文件 env 测试加互斥锁（worker 原已修 + env.rs/otlp.rs/config.rs），**发现并修复 config.rs 双重加锁死锁**（脚本插入锁与原有 `_env_guard` 冲突 → 同线程二次 lock 卡死，infra lib 670 测试全过）
- **A3 并发编译竞争**：clean 后并发 check 实测 0 错误（无法稳定复现），判定为偶发工具链问题，`--jobs 1` 缓解有效（CI 已用）
- **B1 pre-commit 钩子**：`.githooks/pre-commit`（fmt + unwrap 铁律 + clippy），`git config core.hooksPath` 已装
- **B2 release**：保持 lto=fat（25m17s 为发布一次性成本），评估记录
- **B4**：Docker 本机不可用（DB 集成测试 291 ignored 由 CI 容器覆盖）
- **C1 Miri**：nightly+miri 已装，sz-rust-mcp **9 测试全过 0 UB**（首跑 2 失败为过时断言，已修）
- **C2 安全审计**：`cargo-audit` exit 0（588 依赖 0 漏洞）+ `cargo-deny` advisories/licenses/bans 三项全绿；**发现并修复 SQL 注入检测漏检**（validator 原仅匹配带引号变体，裸 `DROP`/`; 多语句`/`OR 1=1` 漏检，已补 6 个裸模式，92 测试全过）
