## 5. 架构深评

### 5.1 分层（依据实际依赖方向）

```text
sz-rust-sz300（业务，41 端点）
  router -> panic_guard -> cors -> csrf -> rate_limit -> circuit_breaker -> auth
  controllers -> services -> sz-orm（外部 ../sz-orm）-> MySQL/PG
        |
        v
sz-rust-core（聚合器：13 个强制 facade + image/qrcode/rqrr + addons-loader）
        |
        v
sz-rust-capability（能力注册中心，最底层）

游离层（有代码、无消费者）：
  api-gateway(feature) service-registry(feature) workflow vector-db migration
  addons-{cms,crm,ecommerce,erp,forum,im,operate} admin-ui marketplace mcp ...
```

依赖方向正确、无环。问题不在分层，而在颗粒度与兑现率。

### 5.2 三个亮点

1. 中间件链可解释且与代码一致：`router.rs:405-423` 的叠加顺序与文档严格吻合。
2. WASM 沙箱真实：`wasmi` + fuel + StoreLimits + 两条负向测试（`lib.rs:144-152`）。
3. 门禁密度罕见：33 个 CI job，除 machete 外基本阻塞。

### 5.3 三个结构性风险

1. 宣传面远大于接线面：12+ crate 无下游，7 个行业插件零引用。
2. core 成为上帝 crate：强制聚合 13 facade 与重型依赖，抵消 facade 分层初衷。
3. 鉴权是单点而非纵深：41 个端点收敛到 11 条精确字符串 + 一条中间件。

## 6. 安全结论

总评 10.5/15。做对：JWT fail-fast/轮换/audience/常量时间、bcrypt spawn_blocking、CSRF 双提交、路径穿越三重校验、26 条安全靶场测试、审计链、脱敏、安全头。

做错/未做：商户创建越权（P0-3）、上传 URL 401（P0-2）、release panic guard 失效（P1-1）、metrics fail-open（P1-2）、CORS `*`（P1-3）、21 条 RUSTSEC 静音（P1-6）、测试硬编码口令（P2-6）。

结论：内网/单租户可用；公网多租户生产不可用，直到 P0-2/3 与 P1-2/3/6 关闭。

## 7. 性能结论

有数据：release profile 专业（`Cargo.toml:526-534`）；17 个 bench target；CI 要求 ≥11 类；仓库内存在 RSS 9.4 MB 基线工件（非本次实测）。

未验证：无 wrk/k6 压测，p50/p95/p99、RPS、长连接内存增长全部未知；`scripts/perf/regression_gate.sh` 未接 CI；N+1 检测器未接线；GraphQL 用 `pool.acquire().await.ok()?` 吞池耗尽错误。

隐患：上传整文件读（P1-9）、黑名单 O(n)（P1-5）、WASM 阻塞任务不可取消（P1-4）。

## 8. 跨语言对比与适用性

| 方案 | 性能上限 | 内存/启动 | 安全默认 | 生态成熟 | 开发效率 | 人才供给 | 本项目相对位置 |
|---|---|---|---|---|---|---|---|
| ThinkPHP8 | 低 | 中 | 弱 | 极成熟 | 高 | 极多 | 框架能力已超，生态远不如 |
| C++ Drogon/oatpp | 极高 | 低/中 | 弱 | 中 | 低 | 少 | 安全性/DX 更好，纯吞吐不如 |
| C# ASP.NET Core | 高 | 中/高 | 强 | 极成熟 | 高 | 多 | 内存与单二进制更优，企业集成不如 |
| Rust axum+tower | 高 | 低 | 中 | 成熟 | 中 | 中 | 本项目 = axum+tower+业务套件 |
| Loco | 高 | 低 | 中 | 成长中 | 高 | 少 | Loco 完整度更高，本项目安全件更厚 |
| Actix Web | 极高 | 低 | 中 | 成熟 | 中 | 中 | Actix 裸吞吐更强，本项目 tower 兼容更好 |

建议重写：值得 C++ 的是图像/二维码流水线（当前 `image`+`rqrr`+`qrcode` 强制在 core）；值得 C# 的是后台管理端、Windows 设备 SDK、ERP/SAP 连接器、复杂报表。Web 层、认证、ORM 不建议重写。

互操作：addon 使用 `extern "Rust"` ABI（`hot_reload.rs:176`），C++/C# 无法消费。不可信插件继续 WASM；可信跨语言扩展走 gRPC/sidecar；若必须 C ABI，应独立 `sz-rust-capi` 隔离 unsafe。不推荐 P/Invoke。
