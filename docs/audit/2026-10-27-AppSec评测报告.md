## 4. 优点清单（附证据）

1. **SQL 注入防护纪律**：sz300 全部 `?` + params 参数化（device_service.rs:15,88,110），无用户输入拼接进 SQL 文本；`query_as!` 零使用，raw SQL 均为静态常量。
2. **认证 fail-fast 与强度**：`SZ300_JWT_SECRET` 缺失即 panic（main.rs:192-193），JWT 密钥强度 ≥32 字节强制（mvc-facade/src/controller.rs:120-131）。
3. **CSRF 实现正确**：双提交 Cookie，`SameSite=Strict; Secure`（auth.rs:30），常量时间比较防时序（health.rs:155-164 / csrf.rs），且 `Secure` 标志有专项单元测试（auth.rs:205-220）。
4. **路径遍历三重防护**：`resolve_upload_path` 字符串 `..` 拦截 + canonicalize + 前缀边界校验（file_serve.rs:27-49），14+ 变体单元测试锁定。
5. **WASM 沙箱三重限制**：fuel 10M / 内存 256MiB / 5s 超时 + `spawn_blocking`（wasm/src/lib.rs:17-23、wasm_api.rs:70-94），P0 修复已闭环（ADR-044）。
6. **无 SSRF/XXE 面**：全仓库无用户可控 URL 拉取端点；XML 解析仅 quick-xml（流式、不解析 DTD 外部实体），无 XXE 配置面。
7. **日志脱敏**：`auth_service.rs:179` `#[tracing::instrument(skip(password))]`、`:363` skip token；审计日志仅 host/status/duration/model（ai-facade audit.rs:115-146）。
8. **限流防代理头绕过**：`trust_proxy_headers` 默认 false（config.rs:371-429），X-Forwarded-For 伪造无法绕过限流（rate_limit.rs:212-235）；login 端点被限流。
9. **unsafe 治理**：`unsafe_code = "forbid"`（Cargo.toml:121），仅 4 处 `#![allow]` 均带 Safety 注释（mem_pool.rs:137-162、simd_str.rs:175-217）。
10. **确定性安全验证**：26 项 gauntlet 用真实 TCP 原始请求（非 tower::oneshot）驱动，绑定 `127.0.0.1:0`，本机复跑 **26 passed / 0 failed**（见第 9 节）。
11. **供应链治理成熟**：deny.toml 每条 ignore 均带 reason 与升级条件（如 zip 2.4.2 标注「无补丁 2.x，需 MSRV 1.88，升级父 crate 后移除」）。

## 5. 缺陷清单（按优先级）

### P0（必须修）

- **P0-1：插件签名校验是「假实现」——仅检查长度，不验证 Ed25519 签名。**
  - `plugin_manager.rs:183-191`：`verify_signature()` 只要求 `signature.len() >= 64` 且公钥非空，**未做任何密码学验证**；注释自认「简化实现，生产环境应使用 ed25519-dalek 做完整签名验证」。
  - 讽刺的是 `ed25519-dalek = "2"` 已在 workspace 依赖（Cargo.toml:342），但未接线。
  - 影响：任何攻击者可伪造 64 字节签名 + 非空公钥，安装任意恶意插件包（插件为 WASM，受沙箱限制；但完整性保障形同虚设）。缓解因素：安装端点受 JWT 保护、插件运行于 WASM 沙箱。
  - 修复路径：用 `ed25519-dalek` 对 `public_key` + package 哈希做真实验签；为 `PLUGIN_PUBLIC_KEY` 提供正式密钥管理。

### P1（应该修）

- **P1-1：native 插件热加载无完整性校验 = 任意代码执行面。**
  - `hot_reload.rs:347-349` 用 `libloading::Library::new` 直接加载 `addons/` 下的 `.dll/.so/.dylib`，无签名/哈希校验；`hot-reload` feature 在 sz300 默认关闭，但开启后即暴露该面。攻击者若能在服务器写入文件（如通过上传漏洞或已失陷进程）→ 加载恶意库 → RCE。
  - 建议：至少对动态库做 SHA-256 白名单校验，或限制 `addons/` 目录权限 + 审计文件完整性。
- **P1-2：sz300 `default = []`，全部安全加固 opt-in。**
  - `packages/sz-rust-sz300/Cargo.toml [features] default = []`：`v18-security-headers`（安全响应头）、`v18-data-mask`（数据脱敏）、`v18-key-rotation`（密钥轮换）、`v18-rbac`（RBAC）、`v19-jwt-audience`（JWT audience）、`v18-audit-chain`（审计链）**默认全部不启用**。
  - 影响：默认生产构建无 HSTS/CSP/X-Frame-Options、无数据脱敏、无密钥轮换、无细粒度授权。
  - 建议：将 `v18-security-headers`、`v19-jwt-audience`、`v18-data-mask` 纳入默认 features（或提供独立的 `default-security` profile）。
- **P1-3：`/metrics` 默认公开。**
  - `health.rs:138-145`：`metrics_token` 为 `None` 时 `is_metrics_token_valid` 恒返回 true → `/metrics` 公开。配置 `SZ300_METRICS_TOKEN` 后才需鉴权。系统指标（内存/CPU/连接池）可被未认证用户读取；若再叠加 Prometheus 抓取配置暴露，可辅助攻击者评估目标。
  - 建议：生产默认要求 token（如 `SZ300_METRICS_TOKEN` 缺失时启动 WARN 并拒绝对 `/metrics` 的远程访问）。
- **P1-4：TLS 完全依赖外部终止，Docker 默认裸 HTTP。**
  - `main.rs:292-295` 使用 `axum::serve` 纯 HTTP；`Dockerfile` 暴露 8300 明文；`docker-compose.yml`/`docker-compose.prod.yml` 均无 TLS。仅 k8s ingress 配了 `cert-manager` + `ssl-redirect`。
  - 影响：若用户按 Docker 文档直接部署（无 nginx/ingress），认证流量（JWT/CSRF Cookie 带 `Secure` 标志）将明文传输，且 `Secure` Cookie 在 HTTP 下不会被浏览器保存 → CSRF 防护失效。
- **P1-5：refresh 端点为 no-op stub，logout 无 token 黑名单。**
  - `auth.rs:179-183` refresh 不轮换 token；logout 仅清 CSRF Cookie，JWT 无服务端黑名单（无状态 JWT 可接受，但配合 refresh stub 意味着 token 一旦泄露，有效期 24h 内无法撤销）。
- **P1-6：CORS 默认 `Allow-Origin: *`。**
  - `cors.rs:60-66` + `router.rs:75`：未配置 `SZ300_CORS_ORIGIN` 时回退 `*`（不带凭据，无 CSRF 风险）。风险在于浏览器端若将 Bearer token 存 localStorage 并被 XSS 读取，任意站点可发跨域请求；生产应强制配置 origin 白名单。
- **P1-7：供应链忽略 20+ 安全公告，含真实可利用类型。**
  - 重点：`rustls-webpki` CRL/name-constraints 校验绕过（RUSTSEC-2026-0049/0098/0099/0104/0382，依赖 native-roots 缓解）；`zip 2.4.2` SUID/符号链接（RUSTSEC-2026-0367/0368/0369，经 rust_xlsxwriter 引入但**仅构建期嵌入 xlsx/dist 使用，无运行时解压攻击面**，audit.toml 已注明）；`rsa` Marvin 攻击（RUSTSEC-2023-0071，仅公钥验签缓解）。
  - 理由充分、缓解合理，但**应建立季度复审机制**，并关注上游升级（如 zip→8.x 需 MSRV 1.88，与 workspace 1.81 冲突）。

### P2（建议修）

1. **AI 端点直通 LLM**（ai.rs:22-69）：有模型白名单 + 16k 字符上限 + 审计日志，但无系统提示词隔离，prompt injection 属特性固有风险；建议对输出做敏感信息过滤（已有 `data-mask` 可接线）。
2. **图像/Excel/PDF 解析库处理用户上传**：`image`/`imageproc`/`lopdf`/`calamine`（quick-xml）解析不可信文件，这些库内部含 unsafe；cargo-geiger 仅 advisory，建议对上传解析端点做资源限制（超时/内存上限）并定期升级。
3. **api-gateway forwarder 硬编码 `http://` 内部转发**（forwarder.rs:104-107）：内网明文转发，通常可接受，但跨主机的服务网格场景应支持 TLS。
4. **RBAC 无专项测试**：`v18-rbac` 功能存在但缺少水平越权/垂直越权的集成测试（gauntlet 未覆盖）。
5. **无 DAST/渗透工具接入**：安全验证全靠自研 gauntlet + cargo-audit；未接入 OWASP ZAP/nuclei 等 DAST，建议在 CI 或发布前跑一次自动扫描。
6. **`rkyv`/`zerocopy` 为幻影依赖**（serializer.rs 未实际调用）：建议从 Cargo.toml 移除，缩小攻击面与误报。

## 8. 生产就绪度结论（AppSec 视角）

**框架具备发布级安全工程水准，但「默认配置」不满足生产安全基线，且存在一个必须修复的真实弱点（P0-1 插件伪验签）。**

- 可以放心：注入防护、认证、路径遍历、WASM 沙箱、日志脱敏、供应链治理、确定性安全验证（26 项实测通过）。
- 必须处理：① 插件签名改为真实 Ed25519 验签；② 生产部署启用安全头/脱敏/audience 等默认安全 feature；③ `/metrics` 默认需 token；④ 明确 TLS 终止要求（Docker 部署文档需加反向代理模板）；⑤ 对 `服务器信息.md` 中的明文私钥做轮换并收敛权限。
- 结论：**修完 P0-1 并将安全 feature 纳入默认后，可视为「默认安全（secure-by-default）」达标。**
