## 5. 缺陷

### 5.1 新引入项（复跑发现）

#### N1（P2，新观察）：WASM 端点缺 `/api/v1/` 版本前缀

- **证据**：`packages/sz-rust-sz300/src/router.rs:125` `.route("/api/wasm/execute", post(wasm_api::execute))`；对比 :121-158 其他业务端点统一 `/api/v1/`（`/api/v1/ai/chat`、`/api/v1/auth/login`、`/api/v1/merchant/list`、`/api/v1/product/list` 等）。
- **影响**：API 版本化不一致。未来 WASM API 变更难做 major version 升级（无 `/v1/` 前缀无法平滑切 `/v2/`）；对 API 消费方（前端/网关），WASM 端点看起来像"另一套 API"而非 v1 的一部分。
- **建议**：改为 `/api/v1/wasm/execute`，与业务端点统一版本前缀。
- **优先级**：P2（功能不受影响，仅版本化一致性）。

#### N5（P2，新观察）：developer-guide / api-reference 未说明 HTTP 200 + 信封 code 约定

- **证据**：`packages/sz-rust-mvc-facade/src/controller.rs:1078-1079` `assert_eq!(resp.status(), StatusCode::OK); // 业务错误 HTTP 仍 200`——业务错误返回 HTTP 200 + 信封 `{code:0, msg:"..."}`，鉴权错误才用 401/403（merchant.rs:50/101/133）。这是对齐 ThinkPHP `renderJson` 的设计取舍。但 `docs/developer-guide.md` 与 `docs/api-reference.md` 均未说明此约定。
- **影响**：从 REST/HTTP 习惯来的用户（Rust 后端画像 P2 小陈、API 网关/监控配置者）会困惑：为什么错误响应不是 4xx？curl/监控按 HTTP 状态码判失败时会漏掉业务错误。对目标用户（TP 迁移者）友好，对非目标用户不直观。
- **建议**：在 developer-guide.md §3 或 api-reference.md §5 补一句"对齐 ThinkPHP：业务错误 HTTP 200 + 信封 `code:0/-1`，鉴权/越权错误才用 401/403；API 网关需按信封 code 判失败"。
- **优先级**：P2（文档补述，非功能缺陷）。

### 5.2 仍开放项（行为未变，文档缓解）

#### N3（P2，降级自基线 P0-1）：admin_demo 退出行为未变

- **证据**：`packages/sz-rust-examples/src/bin/admin_demo.rs:138-140` 仍是 `drop(router); Ok(())`——打印后立即退出，无 HTTP 服务监听。整改选择"README + examples.md 文档标注 headless"而非"让 admin_demo 真正可访问"。
- **影响**：对 P3 决策者画像，文档透明度已够（README.md:111 + examples.md:13 诚实标注"打印后退出，无 HTTP 服务"），预期落差消除；但理想状态应提供一个真正可运行的 admin 示例（哪怕 mock DB + 真实 HTTP 监听 + 一句"访问 http://127.0.0.1:PORT/api/admin/..."）。当前用户想"看到 admin 跑起来"仍需自行接线。

### 5.3 设计取舍（非缺陷，记录供决策参考）

#### N2（设计取舍）：业务错误 HTTP 200 + 信封 code:0

- **证据**：controller.rs:1078-1079 注释明确 `// 业务错误 HTTP 仍 200`；对齐 PHP `renderJson($code=1, $msg, $data)` / `renderError($msg, $data, $code=0)`。
- **定性**：这是对齐 ThinkPHP 的**有意设计**，对目标用户（TP 迁移者）友好。对 REST 纯粹主义者/HTTP 标准主义者是反模式，但项目定位明确"对标 ThinkPHP 8"，故不列为缺陷。关联 N5（文档应说明此约定）。

#### N4（设计取舍）：65 crate workspace 认知负荷

- **证据**：README.md:149 `全部 65 个 crate 在同一 workspace`；developer-guide.md:30 ORM 入口、api-reference.md:46-49 ORM API 表已降低入口查找成本，但 workspace 规模本身未变。
- **定性**：这是对齐 ThinkPHP"大而全单包"的反向架构选择（Rust workspace 多 crate），developer-guide/api-reference 缓解了入口回忆，但新用户首次 `ls packages/` 仍会感到规模压力。非 UXR 可独立解决，需架构层面评估是否提供"精选 subset"入门路径。
