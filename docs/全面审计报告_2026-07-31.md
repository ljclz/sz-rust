### 3.4 关键缺陷：Mutex/RwLock 中毒级联风险

**严重程度**：High

**问题**：生产代码中大量使用 `.lock().unwrap()` / `.read().unwrap()` / `.write().unwrap()`：

| 模块 | 位置 | 数量 |
|------|------|------|
| szrsql-tx/src/lock.rs | LockManager 全部方法 | 10+ |
| szrsql-tx/src/mvcc.rs | MvccManager begin/commit/abort | 8+ |
| szrsql-tx/src/wal.rs | WalWriter append/flush/truncate | 6+ |
| szrsql-sql/src/executor.rs | dist_runtime 读写 | 3 |
| szrsql-storage/src/btree.rs | height()/search() 路径 | 5+ |

**风险**：若任一线程在持锁期间 panic（如 B+Tree 数据损坏触发 unwrap），Mutex 进入 poisoned 状态，后续所有 `.unwrap()` 调用将级联 panic，导致整个进程崩溃。

**修复方向**：
```rust
// 当前（危险）
let mut table = self.tables[idx].lock().unwrap();

// 建议（容错）
let mut table = self.tables[idx].lock().unwrap_or_else(|e| e.into_inner());
// 或返回 Result
let mut table = self.tables[idx].lock().map_err(|_| LockError::Poisoned)?;
```

## 五、性能审计

### 5.1 执行器模型

**当前状态**：火山模型 + `Vec<Row>` 物化中间结果

```
Executor::execute(&plan) → Vec<Row>  // 全量物化
```

| 问题 | 影响 | 等级 |
|------|------|------|
| 全量物化 | 大结果集 OOM 风险（100万行 × N列） | High |
| 无流式迭代器 | 无法 LIMIT 提前终止（需物化全部再截断） | Medium |
| 无向量化 | 逐行处理，CPU cache 不友好 | Medium |

**文档已声明**：executor.rs 注释 "不引入迭代器树：当前实现用 Vec<Row> 物化中间结果，简化测试与调试"

### 5.2 WAL 性能

| 特性 | 实现 | 评价 |
|------|------|------|
| Group Commit | ✅ batch_threshold=128 | fsync 摊销 |
| CRC32C 校验 | ✅ 硬件加速 | 数据完整性 |
| 原子截断 | ✅ 写临时文件 + rename | 崩溃安全 |
| 批量追加 | ✅ batch_append | 减少系统调用 |

### 5.3 存储引擎

| 特性 | 实现 | 评价 |
|------|------|------|
| B+Tree 阶数 | 256 | 适合磁盘页 |
| BufferPool | 分片 LRU + Pin/Unpin | 并发友好 |
| 脏页刷盘 | 同步/异步双模式 | 灵活 |
| BulkLoad | 批量加载优化 | 大表导入 |

### 5.4 并发模型

| 组件 | 锁类型 | 评价 |
|------|--------|------|
| LockManager | 分片 Mutex（16 shard） | ✅ 减少争用 |
| MvccManager | RwLock | ✅ 读多写少场景适合 |
| WalWriter | Mutex<File> | ⚠️ 写入瓶颈（单文件锁） |
| BufferPool | 分片 LRU | ✅ 并发友好 |

### 5.5 性能风险

| 风险 | 等级 | 说明 |
|------|------|------|
| WAL 单文件 Mutex | Medium | 高并发写入时 fsync 串行化 |
| 执行器无并行算子 | Medium | 无 Parallel Scan / Hash Join 并行 |
| Raft 逻辑时钟 | Low | 测试用，生产需真实定时器 |

## 十、审计结论

SzRSQL 作为 Rust 自研分布式 SQL 数据库，在 v1.0.0-rc.1 阶段展现了**扎实的工程质量**：

- **零 unsafe 代码**，完全依赖 Rust 类型系统保证内存安全
- **零 todo/unimplemented**，所有声明的功能均有实现
- **3,500+ 单元测试 + 141 对抗性测试**全部通过（1 个 CDC 竞态除外）
- **安全体系完备**：TLS 1.3 + SCRAM-SHA-256 + TDE + SQL 防火墙 + 审计哈希链
- **协议兼容性好**：pgwire 核心流程完整，SQLSTATE 映射正确

主要技术债务集中在**性能层**（物化执行器）和**容错层**（Mutex 中毒），均为可修复的工程问题，不存在架构性缺陷。

**发布建议**：修复 3 项发布阻断问题后，可作为 MVP 发布。
