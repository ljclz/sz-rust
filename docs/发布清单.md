# SzRSQL crates.io 发布清单

- 发布版本：`1.0.0-rc.1`
- 适用范围：本 workspace 下全部 18 个 crate
- 仓库地址：https://github.com/szrsql/szrsql
- 文档地址：https://docs.rs/szrsql

> 本文档仅描述发布流程与检查项，**不包含任何 crates.io token**。所有命令由发布者本人在本地终端执行。

---

## 1. 发布前检查项清单

在执行任何 `cargo publish` 之前，必须保证以下检查全部通过（在仓库根目录执行）：

| 序号 | 检查项 | 命令 | 期望结果 |
| --- | --- | --- | --- |
| 1 | 格式化检查 | `cargo fmt --all -- --check` | 无 diff 输出，退出码 0 |
| 2 | 静态分析 | `cargo clippy --workspace --all-targets -- -D warnings` | 无 warning，退出码 0 |
| 3 | 单元 + 集成测试 | `cargo test --workspace` | 全部通过，退出码 0 |
| 4 | 文档构建 | `cargo doc --workspace --no-deps` | 无错误，退出码 0 |
| 5 | 安全审计 | `cargo audit`（需安装 `cargo-audit`） | 无漏洞报告 |
| 6 | 许可证审查 | `cargo deny check licenses`（需安装 `cargo-deny`） | 无违规许可 |
| 7 | 编译检查 | `cargo check --workspace` | 退出码 0 |
| 8 | 干发布验证（每个 crate） | `cargo publish -p <crate> --dry-run` | 全部通过 |

> 任意一项未通过，**禁止**继续发布流程。

## 2. 发布流程（用户自行执行）

### 2.1 登录 crates.io

```bash
cargo login
# 按提示粘贴 crates.io API token（请勿写入任何文件或脚本）
```

### 2.2 按依赖拓扑顺序发布

crates.io 要求被依赖的 crate 必须先发布，因此严格按以下顺序执行。每个 crate 都先 `--dry-run` 验证，再正式发布：

```bash
# 模板：对每个 crate 执行
cargo publish -p <crate-name> --dry-run
cargo publish -p <crate-name>
```

#### 第 1 层（无内部依赖）
```bash
cargo publish -p szrsql-types --dry-run
cargo publish -p szrsql-types
```

#### 第 2 层（依赖 szrsql-types）
```bash
cargo publish -p szrsql-storage --dry-run
cargo publish -p szrsql-storage

cargo publish -p szrsql-sql --dry-run
cargo publish -p szrsql-sql

cargo publish -p szrsql-ops --dry-run
cargo publish -p szrsql-ops
```

#### 第 3 层（依赖 szrsql-types + szrsql-storage）
```bash
cargo publish -p szrsql-tx --dry-run
cargo publish -p szrsql-tx

cargo publish -p szrsql-ai --dry-run
cargo publish -p szrsql-ai
```

#### 第 4 层（依赖 szrsql-types + szrsql-sql）
```bash
cargo publish -p szrsql-catalog --dry-run
cargo publish -p szrsql-catalog

cargo publish -p szrsql-optimizer --dry-run
cargo publish -p szrsql-optimizer

cargo publish -p szrsql-dialect-compat --dry-run
cargo publish -p szrsql-dialect-compat

cargo publish -p szrsql-shadow --dry-run
cargo publish -p szrsql-shadow
```

#### 第 5 层（依赖 szrsql-tx）
```bash
cargo publish -p szrsql-cdc --dry-run
cargo publish -p szrsql-cdc

cargo publish -p szrsql-security --dry-run
cargo publish -p szrsql-security

cargo publish -p szrsql-scheduler --dry-run
cargo publish -p szrsql-scheduler
```

#### 第 6 层（依赖 szrsql-catalog + szrsql-tx）
```bash
cargo publish -p szrsql-protocol --dry-run
cargo publish -p szrsql-protocol
```

#### 第 7 层（依赖 szrsql-protocol + szrsql-sql）
```bash
cargo publish -p szrsql-pgcompat --dry-run
cargo publish -p szrsql-pgcompat
```

#### 第 8 层（依赖 szrsql-cdc + szrsql-tx）
```bash
cargo publish -p szrsql-replication --dry-run
cargo publish -p szrsql-replication
```

#### 第 9 层（依赖 szrsql-cdc + szrsql-replication）
```bash
cargo publish -p szrsql-dist --dry-run
cargo publish -p szrsql-dist
```

#### 第 10 层（最终二进制，依赖几乎所有上层 crate）
```bash
cargo publish -p szrsql-bin --dry-run
cargo publish -p szrsql-bin
```

## 4. 发布后验证项

每发布完一个 crate，立即验证：

| 序号 | 验证项 | 方式 | 期望结果 |
| --- | --- | --- | --- |
| 1 | crates.io 页面可访问 | 浏览器打开 `https://crates.io/crates/<crate-name>` | 页面存在，版本显示 `1.0.0-rc.1` |
| 2 | docs.rs 文档生成 | 浏览器打开 `https://docs.rs/<crate-name>/1.0.0-rc.1` | 文档已构建并可浏览 |
| 3 | 可被外部项目引用 | 新建临时项目，`cargo add <crate-name>@1.0.0-rc.1` 后 `cargo build` | 编译通过 |
| 4 | 依赖链一致 | 检查 crates.io 上各 crate 的 Dependencies 段 | 内部依赖版本均为 `1.0.0-rc.1` |

### 全部发布完成后的整体验证

```bash
# 在一个全新目录中验证
cargo new szrsql-verify
cd szrsql-verify
cargo add szrsql-bin@1.0.0-rc.1
cargo build
```

> 若 docs.rs 文档构建失败，可在 https://docs.rs/about 了解构建日志与重试机制。

## 5. 回滚 / 撤回说明

- crates.io 不支持删除已发布版本，但可在发布后 **72 小时内** 执行 `cargo yank --vers 1.0.0-rc.1 -p <crate-name>` 撤回（yank 后新项目无法解析到该版本，已写入 lockfile 的项目仍可使用）。
- 严重问题应直接发布 `1.0.0-rc.2` 修复版本，并对 `1.0.0-rc.1` 执行 yank。
