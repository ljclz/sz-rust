# SZ-Rust 软件项目审计清单（通用版）

> **文档定位**：适用于任何软件项目的通用审计框架，覆盖工程、安全、合规、性能、可维护性等全维度。本版本在通用清单基础上，针对 SZ-Rust Web 框架场景扩展了 Web 安全审计项（SQL 注入 + XSS + CSRF + 路由安全 + 路径遍历）。

> **使用方式**：
> - 新项目发布前：完成 P0 + P1 全部审计

> - 金融级/生产级认证：完成 P0 + P1 + P2 + P3 全部审计
>
> **版本**：v1.0
> **最后更新**：2026-07-22

### 2.2 安全审计（含 Web 框架专属项）

**目标**：检测已知漏洞、禁用依赖、许可证合规、来源可信；并覆盖 Web 框架专属的安全风险（SQL 注入 / XSS / CSRF / 路由安全 / 路径遍历）。

#### 2.2.1 通用安全检查

- [ ] 漏洞公告扫描（CVE/RUSTSEC/GHSA）通过
- [ ] 无禁用 crate/包
- [ ] 无未维护依赖（或已记录忽略理由）
- [ ] 无 yanked 版本
- [ ] 来源审查（无可疑镜像源）
- [ ] 许可证扫描通过

#### 2.2.2 Web 框架专属：SQL 注入扫描

- [ ] 所有 SQL 语句使用参数化接口（`?` / `$N` 占位符），无 `format!` 拼接
- [ ] 表名/列名通过 `validate_identifier` 白名单校验，无用户输入直接拼接
- [ ] ORDER BY / GROUP BY 子句使用白名单，不直接接受用户输入
- [ ] LIKE 查询转义 `%` 和 `_` 通配符
- [ ] 路由参数不直接进入 SQL 查询条件

**工具**：
- 静态扫描：`grep -rn 'format!\s*([^)]*["'\'']\(SELECT\|INSERT\|UPDATE\|DELETE\)' --include='*.rs'`
- 动态扫描：SQL 注入 fuzz 测试（payload 包含 `' OR 1=1 --` / `; DROP TABLE` / UNION 等）

#### 2.2.3 Web 框架专属：XSS（跨站脚本）扫描

- [ ] 控制器返回的 HTML/JS 片段中无未转义的用户输入
- [ ] 模板引擎默认开启自动转义（Askama / Tera / Handlebars 默认转义）
- [ ] `IntoResponse` 实现不直接拼接用户输入到 `Content-Type: text/html` 响应体
- [ ] JSON 响应的字符串字段经过 `serde_json` 序列化（自动转义 `<` `>` `&`）
- [ ] 错误消息回显时转义（避免反射型 XSS）

**工具**：
- 静态扫描：`grep -rn 'format!\s*("<[^>]*>\{.*\}")' --include='*.rs'`
- 动态扫描：XSS fuzz 测试（payload 包含 `<script>` / `<img onerror>` / `javascript:` 等）

#### 2.2.4 Web 框架专属：CSRF（跨站请求伪造）扫描

- [ ] 写操作（POST/PUT/DELETE/PATCH）有 CSRF 防护
- [ ] 使用 `SameSite=Strict` 或 `SameSite=Lax` Cookie 属性
- [ ] 关键操作校验 `Origin` / `Referer` 头
- [ ] API 接口使用 token-based 认证（JWT/Session ID 在 Header，非 Cookie）
- [ ] 表单提交包含 CSRF Token 并在服务端校验

**工具**：
- 静态扫描：检查中间件链是否包含 CSRF 防护层
- 动态扫描：跨域请求测试（无 Origin/Referer 的 POST 应被拒绝）

#### 2.2.5 Web 框架专属：路由安全扫描

- [ ] 路由参数有类型校验（如 `:id` 必须为数字，非数字返回 404/400）
- [ ] 路由参数有范围校验（如分页 `page >= 1`，`page_size <= 100`）
- [ ] 路由不暴露内部实现细节（如不直接路由到 `/internal/debug`）
- [ ] 多应用前缀无冲突（oapc/admin/api 前缀树不互相覆盖）
- [ ] 通配符路由（`/*`）不暴露敏感路径
- [ ] HTTP method 严格匹配（不默认接受全部 method）

**工具**：
- 静态扫描：路由宏展开检查（`cargo expand`）
- 动态扫描：路由 fuzz 测试（异常路径 / 超长路径 / 编码绕过 / 方法混淆）

#### 2.2.6 Web 框架专属：路径遍历扫描

- [ ] 文件上传/下载接口对文件名做 `canonicalize` + 前缀校验
- [ ] 静态资源服务配置 `tower-http::services::ServeDir` 时启用 `ServeDir::not_found_on_deny`
- [ ] 模板路径不拼接用户输入
- [ ] 日志文件路径不拼接用户输入
- [ ] 配置文件路径不拼接用户输入

**工具**：
- 静态扫描：`grep -rn 'std::fs::.*\(format!\|push_str\)' --include='*.rs'`
- 动态扫描：路径遍历 fuzz 测试（payload 包含 `../` / `..\\` / `%2e%2e%2f` / `....//` 等）

**工具汇总**：
- Rust: `cargo audit` + `cargo deny check`
- Node.js: `npm audit` / `pnpm audit` / `snyk`
- Python: `pip-audit` / `safety` / `bandit`
- Go: `govulncheck` / `nancy`
- 通用: `trivy` / `snyk` / `dependabot` / OWASP ZAP（Web 动态扫描）

**通过标准**：0 未忽略的 Critical/High 漏洞，0 SQL 注入，0 XSS，0 CSRF，0 路径遍历，所有忽略项有明确理由和跟踪计划。

### 2.3 敏感信息审计

**目标**：确保代码库中不包含任何真实生产凭据。

**检查项**：
- [ ] Grep 扫描真实密码（数据库/Redis/API key/Token）
- [ ] Grep 扫描真实公网 IP
- [ ] Grep 扫描真实本机路径（如 `E:\` / `/home/user/`）
- [ ] Grep 扫描真实数据库名/表空间名
- [ ] Grep 扫描真实 SSH 私钥/证书
- [ ] 检查 `.gitignore` 是否排除 `.env` / `*.key` / `*.pem`
- [ ] 检查 Git 历史是否曾泄露凭据（需用 `git log -p | grep`）
- [ ] 验证文档示例使用占位符（`<your-password>` / `example.com`）
- [ ] **Web 框架专属**：检查日志/tracing span 中不输出 Cookie/JWT/密码原文
- [ ] **Web 框架专属**：检查错误响应中不回显内部堆栈/SQL/路径

**工具**：
- `gitleaks` / `trufflehog` / `git-secrets`：自动扫描 Git 历史
- `grep -rE "(password|secret|key|token)\s*[:=]\s*['\"][^'\"]{8,}"`：手动扫描
- 通用正则：`[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}`（IP）

**保留例外**（需明确记录）：
- 测试代码中的本地 `127.0.0.1` + 默认密码（如 `test123`）
- CI service container 初始化密码（必须固定）
- 文档示例占位符（`<your-xxx>`）

**通过标准**：0 真实生产凭据泄露。如发现，**立即修改生产环境密码** + 清除 Git 历史（`git filter-repo`）+ 重新发布。

- Velero（Kubernetes 备份）

**通过标准**：RTO ≤ 15 分钟，RPO ≤ 5 分钟，混沌工程 16 项全通过。

### 4.4 并发安全审计

**目标**：验证并发代码无数据竞争、死锁、锁竞争。

**检查项**：
- [ ] Send/Sync 边界正确（Rust）
- [ ] 锁粒度合理（无过大临界区）
- [ ] 无死锁风险（锁顺序一致）
- [ ] 无数据竞争（原子操作正确）
- [ ] 异步代码无阻塞（async 中无 sync I/O）
- [ ] ThreadSanitizer 检测通过
- [ ] **Web 框架专属**：`State<T>` 共享状态无 `&mut` 逃逸（必须 `Arc<Mutex<T>>` 或 `Arc<RwLock<T>>`）
- [ ] **Web 框架专属**：中间件无 `Send` 边界违反（`tokio::spawn` 要求 `Send`）

**工具**：
- Rust: `cargo miri` / ThreadSanitizer / `loom`
- Node.js: `claudia` / `doctor`
- Python: `threading` 静态分析
- Go: `go test -race` / `go vet -race`

**通过标准**：0 数据竞争，0 死锁，TSan 检测通过。

---

### 4.5 内存安全审计

**目标**：验证无内存泄漏、UAF、DF、buffer overflow。

**检查项**：
- [ ] unsafe 块审查（Rust）
- [ ] 无内存泄漏（Valgrind/ASan 检测）
- [ ] 无 use-after-free
- [ ] 无 double-free
- [ ] 无 buffer overflow
- [ ] 无未初始化内存读取
- [ ] 资源释放正确（RAII / Drop / defer）
- [ ] **Web 框架专属**：请求 body 流式读取无缓冲区溢出（大文件分块）
- [ ] **Web 框架专属**：连接池/会话表无句柄泄漏（长稳测试验证）

**工具**：
- Rust: `cargo miri` / AddressSanitizer / MemorySanitizer
- C/C++: Valgrind / ASan / MSan / UBSan
- Go: `go vet` / `govet -shadow`
- Python: `tracemalloc` / `objgraph`

**通过标准**：MirI 0 报错，Valgrind 0 definitely lost，ASan 0 error。

**工具**：
