### 3.2 事务 ACID 审计

| 检查项 | 状态 | 审计结果 |
|--------|------|---------|
| 原子性（Atomicity） | ✅ 通过 | commit/rollback 状态机 + SSI 检测 |
| 一致性（Consistency） | ✅ 通过 | CHECK/FK/PK/UNIQUE 约束接驳 executor |
| 隔离性（Isolation） | ✅ 通过 | RC/RR/SER 三档 + first-committer-wins |
| 持久性（Durability） | ⚠️ 部分通过 | group commit + fsync，但 commit-then-log 模型有风险 |
| 多语句执行限制 | ❌ 未通过 | ADV-BUG-002：解析器接受 `SELECT 1; DROP TABLE t` 返回 2 条语句 |

> **持久性风险说明**：当前采用 commit-then-log 模型，事务在 WAL 落盘前已向客户端返回成功。若发生 OS 缓冲丢失或断电，可能出现已 ACK 事务丢失。建议评估 log-then-commit 或 group commit + fsync 强化路径。

> **多语句执行风险说明（ADV-BUG-002）**：`szrsql-sql` 解析器在解析 `SELECT 1; DROP TABLE users` 时返回 2 条语句（`parser returned 2 statements`），未提供"单语句模式"开关。若 pgwire 应用层未限制，可能执行注入的第二条语句造成 SQL 注入。修复建议：1）在 `parse_sql` 之外提供 `parse_single_statement` 函数；2）pgwire 服务端默认只执行首条语句；3）文档明确多语句行为。复现命令：`cargo test -p szrsql-sql --test adversarial test_adv_sql_009_multi_statement_injection`。

### 3.3 SQL 注入防护审计

| 检查项 | 状态 | 审计结果 |
|--------|------|---------|
| SQL 注入检测 | ✅ 通过 | 10 类 + 正则匹配 |
| 参数化查询 | ✅ 通过 | PreparedStatement + `$N` 占位符替换 AST |
| 标识符转义 | ❌ 未通过 | 缺失 `quote_ident` / `escape_ident` |
| 白名单校验 | ✅ 通过 | SqlFirewall 6 层检查 |
| 解析器递归深度限制 | ❌ 未通过 | ADV-BUG-001：50 个 OR 链触发栈溢出（DoS） |

> **标识符转义缺失风险**：DDL 语句中表名/列名拼接未做转义，存在二阶 SQL 注入风险。建议在 executor 层补充 `quote_ident` 函数并对所有动态标识符强制转义。

> **解析器栈溢出风险说明（ADV-BUG-001）**：`szrsql-sql` 解析器使用递归下降解析，二值表达式（AND/OR）的左结合性导致递归深度与表达式项数成正比，无深度限制保护。攻击者构造 50 个 OR 链即可触发 `STATUS_STACK_OVERFLOW`（exit code `0xc00000fd`），导致服务拒绝（DoS）。修复建议：1）在 parser 中添加递归深度计数器，超限返回 `ParseError`；2）将二值表达式解析改为迭代式（work list）；3）增加 `max_parser_depth` 配置项（默认 256）。复现命令：`cargo test -p szrsql-sql --test adversarial test_adv_sql_004_long_sql_input`。

## 十二、关键发现（按严重程度）

### 🔴 Critical（阻断发布）

1. **可观测性严重缺失**
   - 现象：14/16 crate 无 tracing 依赖，0 个 `#[tracing::instrument]` span
   - 影响：存储引擎/事务/共识层完全没有可观测性，生产环境运维盲区大，故障定位困难
   - 建议：在 storage/txn/raft 三个核心层引入 tracing，关键路径添加 span 与事件

> ✅ **已修复**：szrsql-pgcompat 占位 crate 已实现完整的 PostgreSQL 兼容性测试套件（1492 行代码，4 个子模块：SQL 语法/SQLSTATE/数据类型/协议合规性）。

### 🟠 High（建议发布前修复）

1. **持久性模型风险（commit-then-log）**
   - 现象：事务在 WAL 落盘前已向客户端返回成功
   - 影响：断电/OS 崩溃可能导致已 ACK 事务丢失
   - 建议：评估切换为 log-then-commit，或强化 group commit + fsync 路径

2. **标识符转义缺失**
   - 现象：缺失 `quote_ident` / `escape_ident`
   - 影响：DDL 中动态标识符拼接存在二阶 SQL 注入风险
   - 建议：在 executor 层补充标识符转义函数并强制使用

3. **unsafe 块缺 SAFETY 注释**
   - 现象：22 处 unsafe（SIMD + FFI）缺少 SAFETY 注释
   - 影响：unsafe 块不变量未文档化，后续维护易引入 UB
   - 建议：按 Rust API Guidelines 为每个 unsafe 块补充 `// SAFETY: ...` 注释

4. **解析器递归深度无限制导致 DoS（ADV-BUG-001）**
   - 现象：解析 50 个 OR 链（`SELECT * FROM t WHERE id=0 OR id=1 OR ... OR id=49`）即触发 `STATUS_STACK_OVERFLOW`（exit code `0xc00000fd`）
   - 影响：远程攻击者可构造长 OR/AND 链导致服务拒绝（DoS）
   - 根因：`szrsql-sql` 递归下降解析器二值表达式左结合性，递归深度与项数成正比，无深度保护
   - 建议：1）添加递归深度计数器，超限返回 `ParseError`；2）改为迭代式解析；3）增加 `max_parser_depth` 配置项（默认 256）
   - 复现：`cargo test -p szrsql-sql --test adversarial test_adv_sql_004_long_sql_input`

5. **多语句执行未限制（ADV-BUG-002）**
   - 现象：解析 `SELECT 1; DROP TABLE users` 返回 2 条语句，未提供单语句模式开关
   - 影响：若 pgwire 应用层未限制，可能执行注入的第二条语句造成 SQL 注入
   - 根因：解析器接受分号分隔多语句，但未提供"单语句模式"开关
   - 建议：1）提供 `parse_single_statement` 函数；2）pgwire 服务端默认只执行首条语句；3）文档明确多语句行为
   - 复现：`cargo test -p szrsql-sql --test adversarial test_adv_sql_009_multi_statement_injection`

> ✅ **已修复**：deny.toml 许可证配置已创建（cargo-deny 0.20.x version = 2 语法，14 种许可证白名单 + 黑名单 + 来源限制），`cargo deny check` 全部通过。

### 🟡 Medium（下个版本修复）

1. **未使用依赖**
   - `szrsql-types` 的 bytes 依赖未使用
   - `szrsql-bin` 有 12 个未直接 use 的内部 crate 依赖
   - 建议：清理未使用依赖，减小编译图

2. **`.lock().unwrap()` 毒化风险**
   - 现象：大量 `.lock().unwrap()` 调用
   - 影响：任一持锁线程 panic 将毒化 Mutex，后续访问全部 panic
   - 建议：评估改用 `parking_lot::Mutex` 或显式处理 PoisonError

3. **sqlx dev-dependency 未统一管理**
   - 现象：szrsql-protocol 的 sqlx dev-dependency 未在 workspace 统一
   - 建议：迁移至 workspace `[workspace.dependencies]`

4. **文档版本号滞后**
   - 现象：部分文档版本号未与 crate 版本同步
   - 建议：建立文档版本同步机制

### 🟢 Low（跟踪观察）

1. **1 处本地路径注释**
   - 现象：SonnetDB 参考路径在注释中（非真实泄露）
   - 建议：清理注释中的本地路径

2. **TODO 注释（trigger.rs Phase 6.5）**
   - 现象：trigger.rs 中存在 Phase 6.5 TODO
   - 建议：跟踪触发器实现进度
