## 一、P3 优先级（SQL 标准完整性 — 核心差距补齐）

> **背景**：P0-P2 完成了架构、功能、竞争力的主体建设。P3 聚焦 SQL:2016 核心特性中尚未实现的缺口，按「分析查询刚需 → 复杂查询刚需 → 约束完整性 → 谓词扩展」排序。

| # | 任务 | 说明 | 涉及文件 | 预估难度 |
|---|------|------|---------|---------|
| **P3-1** | **GROUPING SETS / CUBE / ROLLUP** | SQL:2016 F-9 分析查询核心。`GROUP BY GROUPING SETS ((a,b),(c))`、`GROUP BY CUBE(a,b)`、`GROUP BY ROLLUP(a,b)`；配合 `GROUPING()` 标量函数区分 NULL 来源。执行器需在聚合分组阶段扩展多分组集迭代。 | `ast.rs`（GroupBy 扩展）、`parser.rs`、`executor.rs`（聚合分组路径）、`expr.rs`（GROUPING 函数） | 高 |
| **P3-2** | **LATERAL JOIN** | SQL:2016 T-72。`FROM a JOIN LATERAL (SELECT ... FROM a) b ON ...`，右侧可引用左侧列。执行器需在 NestedLoop Join 中支持逐左行重规划右侧。 | `ast.rs`（TableFactor 扩展 Lateral 标志）、`parser.rs`、`executor.rs`（Join 执行路径） | 高 |
| **P3-3** | **DEFERRABLE 约束** | SQL:2016 F-9。`CONSTRAINT fk DEFERRABLE INITIALLY DEFERRED`，约束检查推迟到事务提交时。涉及外键/唯一约束的延迟检查机制。 | `ast.rs`（ConstraintAttributes）、`parser.rs`、`executor.rs`（约束检查时机）、`mvcc.rs`（提交钩子） | 中 |
| **P3-4** | **OVERLAPS 谓词** | SQL:2016 F-9。`(start1, end1) OVERLAPS (start2, end2)` 时间段重叠判定。语法糖，执行器翻译为区间比较表达式。 | `ast.rs`（Expr::Overlaps）、`parser.rs`、`executor.rs` | 低 |
| **P3-5** | **SQL/JSON 路径表达式** | `JSON_VALUE(json, '$.a.b')`、`JSON_EXISTS(json, '$.a ? (@ > 5)')`、`JSON_QUERY`。在 Json 类型基础上增加路径求值引擎。 | `ast.rs`、`parser.rs`、`expr.rs`（新增 JSON 函数）、新增 `json_path.rs` | 中 |
| **P3-6** | **TEMPORAL 表（SYSTEM_TIME）** | SQL:2011/2016 F-9。`SELECT * FROM t FOR SYSTEM_TIME AS OF '2024-01-01'` 时态查询。需 MVCC 历史版本可见性扩展。 | `ast.rs`（TemporalTable）、`parser.rs`、`executor.rs`（历史扫描）、`mvcc.rs` | 高 |
| **P3-7** | **SQL:2023 JSON 数组/对象构造** | `JSON_ARRAY(1,2,3)`、`JSON_OBJECT('a':1, 'b':2)`、`JSON_QUERY`。补充 JSON 类型生态。 | `expr.rs`（新增函数） | 低 |
| **P3-8** ✅ | **外键级联行为完整化** | 核实 `ON DELETE/UPDATE CASCADE / SET NULL / SET DEFAULT / RESTRICT / NO ACTION` 六种行为是否全部真实执行（当前可能仅部分实现）。 | `executor.rs`（外键检查路径）、`mvcc.rs` | 中 |

## 三、工程规范门禁（每次任务必须执行）

> 完整规范见 `docs/szrsql-engineering-practices.md`。一键执行全部 10 个门禁：`powershell -ExecutionPolicy Bypass -File scripts/gate-full.ps1`

### 3.1 标准门禁（10 个，缺一不可）

| # | 门禁 | 命令 / 检查项 |
|---|------|-------------|
| 1 | 格式 | `cargo fmt --check` |
| 2 | 编译 | `cargo check --workspace` |
| 3 | Clippy | `cargo clippy --workspace --all-targets -- -D warnings` |
| 4 | 测试 | 受影响 crate 全量测试通过 |
| 5 | 文档 | `cargo doc --no-deps --workspace`（无缺失 doc 注释） |
| 6 | 安全审计 | `cargo audit` + `cargo deny check`（无已知漏洞 / 违禁依赖） |
| 7 | 差分 fuzz | SQL 逻辑变更需运行差分 fuzz（`cargo test -p szrsql-sql --test sql_compare`，需本机 PG 18） |
| 8 | 无占位符 | 生产代码无 `todo!`/`unimplemented!`/`unreachable!` |
| 9 | 全 feature 构建 | `cargo build --workspace --all-features`（确保 feature 门控代码均编译） |
| 10 | Phase Pin | 确认本次提交的任务编号与本文档一致，不跨阶段混入 |

### 3.2 AI 约束（12 条，AI 生成代码必须遵守）

| # | 约束 | 说明 |
|---|------|------|
| AI-1 | `unsafe` 注释 | 所有 `unsafe` 块/函数必须有 `// SAFETY:` 注释说明不变量 |
| AI-2 | 无 unwrap/expect | 生产代码禁止 `unwrap`/`expect`（测试代码除外） |
| AI-3 | 无占位符 | 禁止遗留 `TODO`/`FIXME`/`hack` 等占位注释代替实际逻辑 |
| AI-4 | 参数化 SQL | 所有拼接 SQL 必须改为参数化查询，禁止字符串拼接防注入 |
| AI-5 | 提交必有测试 | 每次 AI 提交必须附带测试（单元测试或集成测试），无测试的提交拒绝合入 |
| AI-6 | trait 完整性 | 实现 trait 时必须覆盖所有必需方法，禁止用 `unimplemented!` 占位 |
| AI-7 | 禁止精度丢失 as | 禁止 `as` 转换导致精度/符号丢失（如 `i64 as i32`、`f64 as u64`），用 `TryFrom`/`TryInto` |
| AI-8 | 禁止 Arc 环 | 禁止通过 `Arc<Mutex<>>` 形成引用环导致内存泄漏，用 `Weak` 打破 |
| AI-9 | 提交/回滚对偶 | 有提交路径必须有对等的回滚/清理路径（RAII 或 `Drop`） |
| AI-10 | parking_lot 优先 | 并发原语优先使用 `parking_lot`，禁止裸用 `std::sync::Mutex/RwLock`（性能敏感路径） |
| AI-11 | Page 对齐/边界 | 存储层 Page 操作必须检查对齐与边界，禁止裸指针越界访问 |
| AI-12 | WAL 优先 | 数据变更必须先写 WAL 再落盘，禁止绕过 WAL 直接修改存储 |

### 3.3 五维代码审查（合入前人工/AI 审查）

| 维度 | 检查点 |
|------|--------|
| C- 正确性 | 逻辑是否正确？边界条件？错误路径？ |
| R- 可读性 | 命名清晰？注释充分？复杂度可控？ |
| A- 架构 | 模块边界合理？职责单一？无循环依赖？ |
| S- 安全性 | 注入风险？权限检查？敏感数据泄露？ |
| P- 性能 | 时间复杂度？内存分配？锁粒度？ |

### 3.4 测试残留清理

测试写盘的临时数据（`data/`、`*.log`、`tables.json`、`mutants.out*` 等）完成后立即删除；`target/` 为构建缓存，必要时 `cargo clean`。
