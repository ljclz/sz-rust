## 一、P3 优先级（SQL 标准完整性 — 核心差距补齐）

> **背景**：P0-P2 完成了架构、功能、竞争力的主体建设。P3 聚焦 SQL:2016 核心特性中尚未实现的缺口，按「分析查询刚需 → 复杂查询刚需 → 约束完整性 → 谓词扩展」排序。

| # | 任务 | 说明 | 涉及文件 | 预估难度 |
|---|------|------|---------|---------|
| **P3-1** | **GROUPING SETS / CUBE / ROLLUP** | SQL:2016 F-9 分析查询核心。`GROUP BY GROUPING SETS ((a,b),(c))`、`GROUP BY CUBE(a,b)`、`GROUP BY ROLLUP(a,b)`；配合 `GROUPING()` 标量函数区分 NULL 来源。执行器需在聚合分组阶段扩展多分组集迭代。 | `ast.rs`（GroupBy 扩展）、`parser.rs`、`executor.rs`（聚合分组路径）、`expr.rs`（GROUPING 函数） | 高 |
| **P3-2** | **LATERAL JOIN** | SQL:2016 T-72。`FROM a JOIN LATERAL (SELECT ... FROM a) b ON ...`，右侧可引用左侧列。执行器需在 NestedLoop Join 中支持逐左行重规划右侧。 | `ast.rs`（TableFactor 扩展 Lateral 标志）、`parser.rs`、`executor.rs`（Join 执行路径） | 高 |
| **P3-3** | **DEFERRABLE 约束** | SQL:2016 F-9。`CONSTRAINT fk DEFERRABLE INITIALLY DEFERRED`，约束检查推迟到事务提交时。涉及外键/唯一约束的延迟检查机制。 | `ast.rs`（ConstraintAttributes）、`parser.rs`、`executor.rs`（约束检查时机）、`mvcc.rs`（提交钩子） | 中 |
| **P3-4** | **OVERLAPS 谓词** | SQL:2016 F-9。`(start1, end1) OVERLAPS (start2, end2)` 时间段重叠判定。语法糖，执行器翻译为区间比较表达式。 | `ast.rs`（Expr::Overlaps）、`parser.rs`、`executor.rs` | 低 |
| **P3-5** | **SQL/JSON 路径表达式** | `JSON_VALUE(json, '$.a.b')`、`JSON_EXISTS(json, '$.a ? (@ > 5)')`、`JSON_QUERY`。在 Json 类型基础上增加路径求值引擎。 | `ast.rs`、`parser.rs`、`expr.rs`（新增 JSON 函数）、新增 `json_path.rs` | 中 |
| **P3-6** | **TEMPORAL 表（SYSTEM_TIME）** | SQL:2011/2016 F-9。`SELECT * FROM t FOR SYSTEM_TIME AS OF '2024-01-01'` 时态查询。需 MVCC 历史版本可见性扩展。 | `ast.rs`（TemporalTable）、`parser.rs`、`executor.rs`（历史扫描）、`mvcc.rs` | 高 |
| **P3-7** | **SQL:2023 JSON 数组/对象构造** | `JSON_ARRAY(1,2,3)`、`JSON_OBJECT('a':1, 'b':2)`、`JSON_QUERY`。补充 JSON 类型生态。 | `expr.rs`（新增函数） | 低 |
| **P3-8** | **外键级联行为完整化** | 核实 `ON DELETE/UPDATE CASCADE / SET NULL / SET DEFAULT / RESTRICT / NO ACTION` 六种行为是否全部真实执行（当前可能仅部分实现）。 | `executor.rs`（外键检查路径）、`mvcc.rs` | 中 |

## 三、工程规范门禁（每次任务必须执行）

1. **门禁 1**：`cargo fmt --check`
2. **门禁 2**：`cargo check --workspace`
3. **门禁 3**：`cargo clippy --workspace --all-targets -- -D warnings`
4. **门禁 4**：受影响 crate 全量测试通过
5. **门禁 7**：SQL 逻辑变更需运行差分 fuzz（`cargo test -p szrsql-sql --test sql_compare`，需本机 PG 18）
6. **门禁 8**：生产代码无 `todo!`/`unimplemented!`/`unreachable!`
7. **AI-1**：`unsafe` 必须有 `// SAFETY:` 注释
8. **AI-2**：生产代码无 `unwrap`/`expect`（测试代码除外）
9. **测试残留清理**：测试写盘的临时数据（`data/`、`*.log`、`tables.json` 等）完成后立即删除；`target/` 为构建缓存，必要时 `cargo clean`

## 四、测试注意

- **100M 级超长测试**（8 个）已全部 `#[ignore]`：columnar 2、read_ahead 1、spill 2、toast 1、btree_bench 1、其他 1——需显式 `-- --ignored` 才运行，日常回归不受影响
- **差分测试**需要本机 PostgreSQL 18（`postgres://postgres:test123@127.0.0.1:5432/sz_orm_test`）
- **环境**：Windows 全 workspace 并行编译会内存不足（E0786），用 `-j 2` 限流
