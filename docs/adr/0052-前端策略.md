> **状态**：已接受（2026-11-05）
> **日期**：2026-11-05
> **决策者**：SZ-Rust Team（用户拍板方案 B）

## 背景

sz-rust 定位为 Rust Web 框架，对标 ThinkPHP 8（`packages/sz-rust-core/Cargo.toml:8` description = "SZ-Rust 核心库：HTTP 服务器、路由、控制器、中间件，对标 ThinkPHP 8"），但实际产品形态是**菜市场智能秤 SaaS**。这一产品形态决定了前端策略不是"框架该不该带视图层"的纯技术问题，而是"管理端 / 商户端 / 智能秤端如何分工"的产品架构决策。

`docs/audit/2026-11-04-系统架构师复评报告.md` 将本决策列为三个悬而未决 ADR 中**唯一未决项**：

- `:60` 维度 10「路线图质量」扣分原因明确写"前端策略 ADR 仍未决"；
- `:104`「前端策略 ❌ 仍未决，本轮建议：A 真建 Vue 管理台或 B 永久 headless。**TA 倾向 B**：当前 7 行业插件 + AI/WASM 已是较大面，再建 Vue 管理台会分散精力；headless + OpenAPI 契约 + CLI 已能满足运维」；
- `:153`「TA 倾向『永久 headless + OpenAPI 契约 + CLI』（选 B），把精力集中在数据层深化而非分散到 Vue 管理台」；
- `:260`「前端策略 ADR 决策 | 属于产品决策，本轮仅给建议（倾向 B 永久 headless），不代决」。

2026-11-05 用户拍板**方案 B 永久 headless**，本 ADR 将该决策落盘并界定影响范围与迁移路径。

## 决策

**选定方案 B：永久 headless**——sz-rust 作为纯 API 后端，前端独立 SPA（sz-rust-visual Tauri 桌面 + Vue H5）。

具体条款：

1. **sz-rust 定位为纯 API 后端框架**。控制器统一返回 JSON（`axum::response::Json`），不发展服务端模板渲染作为主路径。`sz-rust-mvc-facade::view`（`SimpleTemplateEngine`）作为对齐 ThinkPHP `think\View` 的能力保留在 facade 层供下游可选使用，但**不作为 sz-rust-sz300 的主路径**，亦不在 core 默认 feature 中强化。
2. **现有业务 SSR 端点 `/page/{template}`（`sz-rust-sz300/src/controllers/view.rs` + `router.rs:127`）按迁移路径下线**，最终态 sz300 所有对外业务端点返回 JSON。
3. **API 文档 UI 端点（Swagger/ReDoc，`openapi.rs:370/375`）保留**——它们是 API 契约的配套工具，属 headless 形态的一部分，不返回业务 HTML。
4. **前端独立仓库 `D:\vue\test\sz-work`（Vue H5）通过 REST API 对接**，本仓库不托管其代码，仅以 OpenAPI 契约（`sz-rust-sz300/src/openapi.rs`）作为对接面。
5. **`sz-rust-visual` Tauri 2.x 桌面应用作为管理端载体**。当前其定位为 SDD 编排可视化画布（`Cargo.toml:8`），本决策将其产品定位演进为"管理端 + SDD 编排画布"双职责，或在其内新增管理端视图模块；具体管理端 UI 实现由 Tauri 前端层（Webview）承载，后端仅提供 API。
6. **多端复用**：纯 API 利于 H5 / Tauri 桌面 / 小程序 / Android（用户偏好 PREFERENCE_20，NDK Native + R8 混淆）共用同一套后端契约，避免 SSR 下每端各写一套服务端模板。
7. **OpenAPI 契约成为前后端唯一对接面**，`sz-rust-sz300/src/openapi.rs` 必须与实际端点保持一致（已有门禁覆盖，见 ADR-050 关联）。

## 后果

### 正面后果

- **与现有架构一致，无需重写**：admin-ui 已是 headless API 库（`Cargo.toml:6` description "后端 API"）、sz-rust-visual Tauri 2.x 已落地（`Cargo.toml:42`）、Vue H5 已就绪（外部仓库 `D:\vue\test\sz-work`）。方案 B 是对现状的**确认与固化**，而非新建。
- **职责清晰**：后端纯 API（Rust 性能优势区间）、前端纯 SPA（Vue 生态优势区间），各自发挥长板，避免 Rust 写模板的生态短板。
- **多端复用**：同一套 REST API + OpenAPI 契约，H5 / Tauri 桌面 / 小程序 / Android 共用，新增端的成本仅为前端 SPA + API 对接，后端零改动。
- **独立部署与独立 release**：API 容器（Docker 多阶段构建，PREFERENCE_1）独立发布至 GHCR；Vue H5 静态资源独立部署；Tauri 桌面独立 release（跨平台打包）。三者 release 节奏解耦。
- **JSON 路径受益于已有性能优化**：ADR-050 gzip 压缩对 JSON 响应收益最大（`product/list` 出网 −82.93%、`order/list` −84.08%，`0050` §后果）；ADR-049 鉴权上下文缓存对纯 API 请求链路优化已实测（`order/list` +43.3% QPS）。SSR 混入 HTML 响应会让压缩谓词、BREACH 防线、脱敏层都增加分支。
- **关闭一个悬而未决 ADR**：复评报告 `:60` 维度 10「路线图质量」扣分原因"前端策略 ADR 仍未决"消除，路线图质量分有望从 8 提升。

### 负面后果

- **首屏性能依赖 SPA bundle**：Vue H5 首屏需拉 JS bundle 后渲染，首屏 TTFB 不含渲染但 FCP 滞后于 SSR。对菜市场 SaaS 后台（内网/熟客场景，非公网内容站）可接受；若未来出现公网落地页需求，由前端独立做预渲染/SSG（Nuxt/Vite SSG），不在后端引入 SSR。
- **SEO 能力弱**：SPA 客户端渲染对搜索引擎不友好。本项目 SEO 需求低（SaaS 后台 + 智能秤，非内容站），可接受；若未来需要 SEO 的公网页面，同上由前端 SSG 解决。
- **现有 `/page/{template}` 端点需迁移下线**：`sz-rust-sz300/src/controllers/view.rs` 的 `render_page` 及 `router.rs:127` 路由需按迁移路径下线，期间存在过渡期维护成本（见下文迁移路径）。
- **Tauri 桌面产品定位演进**：`sz-rust-visual` 当前是 SDD 编排画布（`Cargo.toml:8`），本决策赋予其"管理端"职责，需在 Tauri 前端层新增管理端视图模块或明确双职责分工，存在一定工作量。
- **OpenAPI 契约同步义务**：前后端独立部署后，契约变更需前后端协同，OpenAPI 必须与实际端点保持一致（已有门禁，但跨仓库协同成本高于单体）。

## 影响范围

1. **sz-rust-core**：不再发展模板渲染作为主路径。`sz-rust-mvc-facade::view`（`SimpleTemplateEngine`）保留作为对齐 ThinkPHP `think\View` 的可选能力（facade 层），但 core 默认 feature 不强化模板能力，core Cargo.toml 不引入 askama/maud/tera 作为主依赖（现状已如此，`Cargo.toml` 无 askama/tera 直接依赖）。
2. **sz-rust-sz300**：控制器统一返回 `axum::response::Json`。现有 `controllers/view.rs::render_page`（返回 `Html`）按迁移路径下线；`openapi.rs` 的 Swagger/ReDoc HTML 保留（API 文档工具，非业务 SSR）。
3. **sz-rust-admin-ui**：保持 headless API 库定位（现状已如此），继续发展 RBAC/动态路由/主题/CRUD API。
4. **sz-rust-visual**：Tauri 2.x 桌面应用，产品定位从"SDD 编排画布"演进为"管理端 + SDD 编排画布"。管理端 UI 由 Tauri Webview 层承载，后端仅提供 API。
5. **前端独立仓库 `D:\vue\test\sz-work`**（Vue H5）：通过 REST API 对接 sz-rust-sz300，本仓库不托管其代码，以 OpenAPI 契约为对接面。
6. **多端**：H5 / Tauri 桌面 / 小程序 / Android 共用同一套 API 契约。
7. **部署**：API 容器（Docker 多阶段 → GHCR，PREFERENCE_1）独立；Vue H5 静态资源独立部署；Tauri 桌面独立 release。

## 迁移路径

现有 SSR/模板代码下线路径（针对 `sz-rust-sz300/src/controllers/view.rs::render_page` + `router.rs:127` `/page/{template}`）：

| 阶段 | 动作 | 验收 |
|------|------|------|
| 1. 现状评估 | 确认 `/page/{template}` 端点是否有实际调用方（grep access log / 前端代码引用）。当前 `render_page` 渲染的是内联 demo 模板（`view.rs:29-37` 展示模板名 + 时间），**非业务页面**，预期无外部调用方。 | grep 前端仓库 `D:\vue\test\sz-work` 对 `/page/` 的引用 = 0 |
| 2. 标记待下线 | 在 `controllers/view.rs` 顶部加 `#[deprecated(note = "ADR-052: 永久 headless，模板渲染端点将下线，改用对应 JSON API")]`，并在 OpenAPI 文档中标记 `deprecated: true`。 | `cargo check` 通过；OpenAPI 文档显示 deprecated |
| 3. API 化（若需保留等价能力） | 若 `/page/{template}` 曾提供任何业务数据，将其转为纯 JSON 端点（如 `GET /api/v1/page/{template}` 返回模板变量 JSON），由前端 SPA 自行渲染。当前 `render_page` 仅返回 demo HTML，无业务数据，**预期此阶段为空操作**。 | 新 JSON 端点测试通过 |
| 4. 前端接管 | 前端 SPA（Vue H5 或 Tauri 桌面）实现等价页面（若需要）。当前 demo 页无业务价值，**预期此阶段为空操作**。 | 前端页面验收通过 |
| 5. 下线模板代码 | 移除 `router.rs:127` `/page/{template}` 路由；移除 `controllers/view.rs`（或仅保留 `html_escape` 工具函数若有其他引用）；移除 `controllers/mod.rs:27` `pub mod view;`。 | `cargo test -p sz-rust-sz300` 通过；`/page/` 路由 404 |
| 6. mvc-facade::view 保留 | `sz-rust-mvc-facade/src/view.rs`（`SimpleTemplateEngine`）**保留**，作为对齐 ThinkPHP `think\View` 的可选能力供下游非 sz300 场景使用，不在本决策中删除。 | facade 测试仍通过 |

> **注**：阶段 1 评估若发现 `/page/{template}` 确有外部调用方，则需按 2→3→4→5 顺序完整执行；若确认无调用方（预期），可跳过 3/4 直接 2→5。下线动作建议作为独立 PR，与本 ADR 落盘分离。

## 验收标准

1. **sz-rust-sz300 所有对外业务端点返回 JSON**：`grep -rn "Html(" packages/sz-rust-sz300/src/controllers/` 仅命中 `openapi.rs`（Swagger/ReDoc 文档 UI），无业务控制器返回 `Html`。
2. **`/page/{template}` 路由下线**：`grep -n "/page/" packages/sz-rust-sz300/src/router.rs` 无命中；`cargo test -p sz-rust-sz300` 通过。
3. **前端独立部署**：Vue H5（`D:\vue\test\sz-work`）与 sz-rust API 容器分别部署，无同仓库耦合。
4. **Tauri 桌面可独立 release**：`packages/sz-rust-visual` 可独立 `cargo build --release` 产出桌面二进制，不依赖 sz300 运行时（通过 API 对接）。
5. **OpenAPI 契约与实际端点一致**：`sz-rust-sz300/src/openapi.rs` 覆盖所有业务端点，门禁（doc-code-consistency）通过。
6. **本 ADR 已登记**：`docs/adr/` 编号 0052 连续；复评报告 `:104`/`:153` 的"前端策略未决"状态可在此 ADR 落盘后标记为已闭环。

## 注意事项

- **本 ADR 是产品架构决策，非纯技术决策**。复评报告 `:260` 明确"属于产品决策，本轮仅给建议（倾向 B 永久 headless），不代决"。本 ADR 由用户拍板，落盘即生效。
- **mvc-facade::view 不删除**。`SimpleTemplateEngine`（`mvc-facade/src/view.rs:260`）是对齐 ThinkPHP `think\View` 的框架能力，保留供下游非 sz300 场景（如独立 SSR 工具、CLI 渲染）可选使用。本决策仅规定**sz300 不将其作为主路径**，不在框架层删除。
- **askama/tera workspace 依赖不删除**。workspace `Cargo.toml:127/372` 的 askama/tera 被 `sz-rust-frontend-codegen`（代码生成）/`sz-rust-sdd`（SDD 模板）/`sz-rust-cli`（CLI 模板）使用，均非 SSR，不在本决策范围。
- **若未来出现公网 SEO 落地页需求**：由前端独立做 SSG（Nuxt/Vite SSG）或预渲染，**不在后端引入 SSR**。若届时评估确需后端 SSR，应新开 ADR 推翻本决策，不得在本 ADR 范围内悄悄 reintroduce。
- **Tauri 桌面管理端实现**：本 ADR 界定 sz-rust-visual 作为管理端载体，但具体管理端 UI（路由、页面、组件）由 Tauri 前端层实现，属后续工作，不在本 ADR 落盘范围内。
- **与 ADR-050 的协同**：纯 JSON 路径使 gzip 压缩谓词、BREACH 防线、脱敏层均无需为 HTML 响应增加分支。下线 `/page/{template}` 后，`controllers/` 下无 `Html` 返回，压缩层 `DefaultPredicate` 对所有业务响应统一按 JSON 处理。

## Bug 定位提示

- 前端调用 sz300 API 返回 HTML 而非 JSON：先查是否命中残留的 `/page/{template}` 路由（迁移未完成），再查控制器是否误用 `Html` 返回（应改 `Json`）。
- Tauri 桌面无法独立 release：检查 `sz-rust-visual` 是否引入了 sz300 运行时依赖（应仅通过 HTTP API 对接，不直接依赖 sz300 crate）。
- OpenAPI 契约与实际端点不一致：跑 `node scripts/audit/doc-code-consistency.js`（门禁 19，铁律 24），按报告修正 `openapi.rs`。
- 关键代码路径：`packages/sz-rust-sz300/src/controllers/view.rs`（待下线的 `render_page`）、`packages/sz-rust-sz300/src/router.rs:127`（待移除的路由）、`packages/sz-rust-admin-ui/src/lib.rs`（headless API 库，保持）、`packages/sz-rust-visual/src/lib.rs`（Tauri 桌面，管理端载体）、`packages/sz-rust-mvc-facade/src/view.rs`（模板引擎 facade，保留）。
