> **状态**：已接受（2026-11-06）
> **日期**：2026-11-06
> **决策者**：SZ-Rust Team（架构分析师）
> **关联 ADR**：[ADR-017](0017-sz-rust-core拆包策略-Facade渐进提取.md)（Facade 渐进提取）、[ADR-018](0018-facade-独立发布策略.md)（Facade 独立发布）、[ADR-019](0019-P3剩余模块解决-四簇提取.md)（四簇提取）、[ADR-041](ADR-041-v1-7-0-feature-gate-isolation.md)（v1.7.0 feature gate 隔离）、[ADR-043](ADR-043-ai时代单一版本合并.md)（AI 时代单一版本合并，56→65 crate）、[ADR-052](0052-前端策略.md)（前端策略，admin-ui/visual 定位）
> **关联评测**：`docs/audit/2026-11-04-系统架构师复评报告.md`
> **验证方法**：`cargo tree --workspace -i <pkg>` 反向依赖核验 + 各包 `Cargo.toml` 依赖图静态分析 + `src/` 代码量统计

---

## 背景

sz-rust workspace 经历三次大规模拆包/合包：

1. **ADR-017/018/019（2026-08-03）**：sz-rust-core 渐进提取 11 个 facade crate（P2/P3 拆包），核心包从"巨石"拆为"facade 集合"。
2. **ADR-041（2026-10-03）**：v1.7.0 新增 27 个功能模块，跨 15 个新增 crate，通过 feature gate 隔离。
3. **ADR-043（2026-10-25）**：AI 时代单一版本合并，企业版 9 crate 并入，workspace 从 56 → 65 members。

三次扩张后，workspace 达到 **65 个成员包**（含根包 sz-rust 则 66）。包数量本身不是问题，但需评估：

- 是否存在**孤儿包**（无消费者，编译产物无人引用）？
- 是否存在**过度拆分**（facade 套 facade、空壳包）？
- 是否存在**可合并包**（功能重叠或同质包）？
- 65 包的**编译时间 / 维护成本 / 认知负担**是否可接受？

本 ADR 基于全量静态分析（65 个 `Cargo.toml` 依赖图 + `cargo tree --workspace -i` 反向依赖核验 + `src/` 代码量统计）产出架构债评估与合并建议。

### 2. Facade 模式分析

#### 2.1 Facade 层级（无套娃）

| 层级 | Facade | 说明 |
|------|--------|------|
| L0 基础 | http / state / auth / pay / router / orm | 无内部 facade 依赖 |
| L1 单跳 | cache → orm；infra → orm + config-center；orm-ext → orm | 单层依赖 |
| L2 多跳 | middleware → orm + cache + http + infra + auth；mvc → http + infra + middleware + orm + state | 多层依赖 |
| L3 聚合 | `sz-rust-facade` → cache + orm + state + middleware + infra + http | 聚合 6 个 facade |

**结论**：无 facade 套 facade 的过度抽象（L3 聚合 facade 是合理的 PHP `think\facade\*` 对齐，但当前为孤儿包）。

## 影响评估

### 1. 编译时间

65 个包的 workspace 在隔离环境（`CARGO_TARGET_DIR=D:/rust-target-verify`）下 `cargo check --workspace` 耗时约 3-5 分钟（增量）/ 15-25 分钟（全量）。26 个孤儿包中：

- **零代码引用的孤儿包**：仍需编译其自身 + 依赖链，但不会触发下游重编译。
- **传递性孤儿包**（visual/sdd）：编译 sdd 会拉入 visual + rag + capability + mcp 链，增加约 30 秒。
- **addons-operate（19036 行）**：最大孤儿包，编译耗时约 15-30 秒，纯浪费。

**估算**：删除 26 个孤儿包可节省约 **15-20%** 全量编译时间。

### 2. 维护成本

| 维护项 | 当前成本 | 孤儿包影响 |
|--------|---------|-----------|
| Cargo.toml workspace.dependencies 条目 | 65 条内部依赖 + 60+ 外部依赖 | 26 个孤儿包的 workspace.dependencies 条目纯维护负担 |
| CI `cargo check --workspace` / `cargo clippy --workspace` | 27 job CI 矩阵 | 26 个孤儿包每个都跑 check/clippy/test，浪费 CI 资源 |
| cargo-machete 白名单 | 31 条 ignored | 孤儿包的 optional 转发依赖需维护白名单 |
| 文档同步（README/CHANGELOG/ADR） | 65 包需在新增/删除时同步 | 孤儿包变更仍触发文档同步门禁 |
| 版本发布（crates.io） | 65 crate 需协调版本 | 孤儿包发布无消费者，纯版本管理负担 |

### 3. 认知负担

新开发者面对 65 个包需理解：

- 哪些是核心（2 个）？哪些是 facade（13 个）？哪些是能力（32 个）？
- 为什么 `sz-rust-tracing` 和 `sz-rust-observability` 都做追踪？
- 为什么 `sz-rust-facade`（聚合）和 11 个基础 facade 并存？
- 为什么 7 个 addons 模板包存在但无消费者？
- `sz-rust-addons-operate` 的 19036 行代码是什么？

**认知负担评分**：高（65 包远超 Dunbar's number 150 的舒适区下限，且 40% 为孤儿包，增加"这个包是干什么的？谁在用？"的探索成本）。

## 建议方案

### 方案 A：激进合并（65 → 30 包）

**操作**：
1. 删除 24 个直接孤儿包（保留 sz300/examples/addon-example/facade-tests 4 个叶子包）。
2. 合并 `sz-rust-tracing` → `sz-rust-observability`。
3. 合并 `sz-rust-alert-engine` + `sz-rust-log-aggregator` → `sz-rust-observability`。
4. 合并 3 个 UI 包 → `sz-rust-admin-ui`（headless API 统一）。
5. 合并 `sz-rust-zerocopy` → `sz-rust-orm-facade`。
6. 删除 `sz-rust-facade`（聚合 facade，孤儿）。
7. 7 个 addons 模板包移至 `examples/` 或独立仓库。

**结果**：65 → 约 30 包。

**优点**：编译时间降低 30-40%，认知负担大幅降低，维护成本降低。
**缺点**：破坏 ADR-043 的"单一版本全量开源"承诺；addons 模板包移出后失去 crates.io 可发现性；UI 包合并后职责模糊；不可逆删除后恢复成本高。

### 方案 B：渐进合并（65 → 50 包）✅ 推荐

**操作**（分阶段，见"实施路径"）：
1. **阶段 1**：删除 8 个极薄孤儿包（zerocopy/log-aggregator/benchmark-suite/pipeline/plugin-sdk/i18n/vector-db/codegen-loop），共约 5,000 行。
2. **阶段 2**：合并 `sz-rust-tracing` → `sz-rust-observability`（消除职责重叠）。
3. **阶段 3**：合并 `sz-rust-alert-engine` + `sz-rust-log-aggregator`（如阶段 1 未删）→ `sz-rust-observability`。
4. **阶段 4**：7 个 addons 模板包标注"template crate，非核心依赖"，在各自 README + workspace README 标注用途，不删除。
5. **阶段 5**：3 个 UI 包 + `sz-rust-facade` 在 README 标注"headless API / 聚合 facade，按需启用"，不删除。

**结果**：65 → 约 55 包（阶段 1-3 删 8 + 合 3 = 净减 10），实际约 55 包。

**优点**：低风险，可逆，保留 ADR-043 承诺，消除职责重叠，渐进降低维护成本。
**缺点**：降幅有限（仅 15%）， addons 模板包仍为孤儿。

### 方案 C：保持现状 + 文档标注

**操作**：
1. 在 `docs/adr/README.md` 新增"包用途速查表"，标注每个包的分类/消费者/是否孤儿。
2. 在每个孤儿包的 `Cargo.toml` `description` 字段追加 `[orphan: <reason>]` 标注。
3. CI 新增 `scripts/audit/orphan-check.js`，检测孤儿包并在 PR 中标注警告（不阻塞）。

**结果**：65 包不变。

**优点**：零风险，零代码变更，纯文档改善。
**缺点**：不解决编译时间/维护成本问题，架构债持续累积。

## 推荐方案 + 理由

**推荐方案 B（渐进合并）**。

**理由**：

1. **ADR-043 约束**：AI 时代单一版本合并承诺要求"65 crate 全量开源"，方案 A 删除 35 包违反该承诺；方案 B 仅删 8 个极薄孤儿包 + 合并 3 个职责重叠包，不破坏承诺实质。

2. **风险可控**：阶段 1 删除的 8 个包均为 < 1000 行的极薄孤儿包，零消费者，删除后 `cargo check --workspace` 可立即验证无破坏。阶段 2-3 的合并涉及 `sz-rust-observability`（已被 sz300 + ai-facade 依赖），需迁移测试但风险可控。

3. **addons 模板包保留**：7 个 addons 模板包（共 27,343 行）是 ADR-043 从企业版合并的行业插件，设计意图是"可作项目起点"。删除它们会失去 crates.io 可发现性，且 `sz-rust-addons-operate` 的 19036 行可能包含有价值的 CRUD 参考实现。方案 B 保留但标注用途，让用户按需采用。

4. **UI 包保留**：ADR-052 已将 `sz-rust-admin-ui` 定位为 headless API 库，`sz-rust-visual` 定位为 Tauri 管理端载体。这 3 个 UI 包是产品形态演进的基础设施，删除会违反 ADR-052。

5. **渐进可逆**：每个阶段独立验证，若发现问题可回退。方案 A 的大规模删除不可逆。

## 后果

### 正面后果

- **阶段 1-3**：净减 10 包（65 → 55），删除约 7,000 行死代码，编译时间降低约 8-10%。
- **阶段 4-5**：认知负担降低，新开发者可通过"包用途速查表"快速定位。
- 消除 `sz-rust-tracing` 与 `sz-rust-observability` 的职责重叠。
- 保留 ADR-043 的"单一版本全量开源"承诺（仅删 8 个极薄孤儿包 + 合 2 个，不删 addons 模板/UI 包）。

### 负面后果

- 阶段 1 删除的 8 个包若未来需要（如 `sz-rust-i18n` 多语言支持），需重新创建。
- 阶段 2 合并 tracing → observability 后，`sz_rust_tracing` crate 名不可用（需 `sz_rust_observability::tracing`）。
- addons 模板包仍为孤儿（方案 B 不删），CI 仍需编译它们。
- 本 ADR 不改变任何代码（只读分析 + 设计文档），实际合并需另开实施 PR。

### 风险缓解

- 阶段 1 删除前，确认 8 个包的 git history 已归档（可通过 `git log -- packages/<pkg>/` 恢复）。
- 阶段 2 合并前，先在 `sz-rust-observability` 新增 `tracing` 模块并跑通测试，再删除 `sz-rust-tracing`。
- 每个阶段独立提交 + 独立 PR，便于回退。

## 注意事项

1. **本 ADR 为只读分析产出**：不修改任何代码，实际合并需另开实施 PR，按"实施路径"分阶段执行。
2. **孤儿包判定边界**：`cargo tree --workspace -i <pkg>` 不显示 optional 依赖（feature gate 关闭时）。本分析将"仅被 optional feature gate 引用"的包也视为孤儿，因默认不编译。若未来 feature 默认启用，需重新评估。
3. **addons-operate 的 19036 行**：本 ADR 不深入分析其代码内容，建议在阶段 4 实施时由 addons 维护者审查是否含可复用 CRUD 参考实现。
4. **与 ADR-052 的关系**：ADR-052 已将 `sz-rust-admin-ui` 定位为 headless API、`sz-rust-visual` 定位为 Tauri 管理端载体。本 ADR 不推翻 ADR-052，仅标注这两个包的孤儿状态。
5. **crates.io 发布影响**：删除已发布包需 `cargo yank`（不删除已下载版本），新版本不再包含该包。阶段 1-3 实施前需确认无外部用户依赖（GitHub stars/issues 检查）。

## Bug 定位提示

若生产 Bug 源于孤儿包的未维护代码：

1. **确认孤儿包是否在编译产物中**：`cargo tree --workspace -i <pkg>` 若无输出，该包未进入任何编译链，Bug 不可能源于此包。
2. **若 Bug 源于 optional feature 启用的孤儿包**：检查 `SZ300_FEATURES` / `--features` 是否启用了对应 feature gate（如 `v18-security-headers` 启用 `sz-rust-security-headers`）。
3. **tracing 相关 Bug**：若涉及 Span/Tracer，检查是 `sz-rust-tracing`（W3C 传播）还是 `sz-rust-observability`（OTLP exporter），两者职责重叠是已知架构债（本 ADR 阶段 2 合并）。
4. **addons-operate Bug**：`packages/sz-rust-addons-operate/src/` 19036 行 CRUD 逻辑，若 sz300 启用了 operate 插件，Bug 可能源于此包的 CRUD 实现。
