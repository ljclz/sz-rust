# ADR-046：性能工程整改 —— 限流分桶、熔断统计窗口、连接池探活、日志级别、性能门禁重写

- 状态：已接受
- 日期：2026-10-29
- 决策者：SZ-Rust Team（性能工程评测整改）
- 相关评测：`docs/audit/2026-10-29-性能工程评测报告.md`（27/100，grade F）
- 实测环境指纹：Windows 10 19045 / 2× Intel Xeon E5-2640 v4（20C/40T）/ 63.9 GiB / rustc 1.99.1 / Node v24.22.1

## 背景

独立性能评测在默认配置下测得：业务可用吞吐被限流器硬顶在 1.13k rps（429 占 89.95%–94.24%）、
`/health` 稳态上限 4.4k rps 却只用 1.5/40 核（p99 随并发线性劣化至 452 ms）、
业务端点 2.21 ms CPU/请求、日志 4.2k 行/s（单次压测日志 544 MB）。

同时发现**性能门禁本身是可信度最低的一环**：`scripts/perf-regression.js` 从未被任何 workflow 引用，
基线是跨机器硬编码占位值（`/health` 50000 QPS），5 s 短跑 + 只统计成功样本 + 失败计入吞吐，
业务端点 100% 403 仍能输出 6.4k QPS 并"PASS"。

本 ADR 记录 0–30 天路线中的五项决策及其代价。

## 决策

### 1. 限流键：真实对端 IP + 有界桶表 + 共享兜底桶

**问题**：`trust_proxy=false`（默认）时 `extract_client_ip` 无任何 IP 来源，所有请求键恒为 `"unknown"`，
全站共用一个桶；`max_keys` 溢出时 `acquire` 返回 `Err`，而中间件对 `Err` 是 fail-open → 限流可被完全绕过；
`reset_at` 用 `now.elapsed()`（≈0）而模块契约写的是 Unix 毫秒时间戳，`Retry-After` 恒为过期值。

**决策**：
- 从 `ConnectInfo<SocketAddr>` 取对端 IP（`rate_limit.rs:222 peer_ip`）；仅当 `trust_proxy=true` 才解析
  `X-Forwarded-For` / `X-Real-IP`，且必须能解析为 `IpAddr`，垃圾头无法污染键空间（`rate_limit.rs:242`）。
- 桶表保留 `max_keys` 上限，但溢出行为改为：先按 `full_refill` 回收空闲桶，仍满则落入**共享兜底桶**
  （`rate_limit.rs:442 TokenBucket`）——有界内存且语义保持（超载时更严，不会静默失效）。
- `reset_at` 改为真实 Unix 毫秒（`wait_ms` 精确到令牌回补所需时间）。
- `main.rs` 改用 `into_make_service_with_connect_info::<SocketAddr>()`，否则 `ConnectInfo` 不存在。

**代价**：键基数与内存成正比，必须依赖 `max_keys`（默认 10k）+ 空闲回收兜底；反向代理未配置
`SZ300_RATE_LIMIT_TRUST_PROXY=true` 时，所有请求会被视为同一对端 —— 这是**显式的安全默认**，
不是回归（伪造 `X-Forwarded-For` 绕过限流的风险高于单桶限流）。

### 2. 熔断统计窗口：60 个定长时间桶替代 `Vec + retain`

**问题**：单把全局 `parking_lot::Mutex`，每请求 `push` 后对整窗口 `retain`，成本随窗口记录数增长。
同二进制把 `STAT_WINDOW` 改为 1 s（记录数下降 60 倍）：单发生器 4.4k → 6.4–6.7k，8 进程 16.5k → 17.6k，
p99 83 ms → 17.6–23.8 ms；2 逻辑核比 40 LP 低 13%–16%，说明存在串行瓶颈而非算力不足。

**决策**：固定 60 个桶的环形缓冲（`circuit_breaker.rs:80 STAT_BUCKETS` / `:100 ErrorWindow`）。
`record` 为 O(1)（只在 epoch 变化时清槽位），失败时做一次固定 60 槽扫描求 `(failures, total)`，
语义仍是"最近 `stat_window` 内错误率 ≥ 阈值则开闸"。默认 60 s 窗口下桶粒度为 1 s。

**代价**：精度从"精确时间戳淘汰"降为"整桶淘汰"（最多 1 s 的边界模糊，对 60 s 窗口可忽略）；
`HalfOpen → Closed` 时整窗清零（与旧实现清空 `Vec` 等价）。

### 3. 连接池 `test_before_acquire` 默认关闭

**问题**：`PoolConfig::default()` 与 PostgreSQL 池均硬编码 `test_before_acquire(true)`，
每次取连接多一次 `SELECT 1` 往返（业务每请求 3 次 SQL → 变 4 次）。

**决策**：默认 `false`（`db.rs:44`），保留 `SZ300_POOL_TEST_BEFORE_ACQUIRE` / `SZ_PG_POOL_TEST_BEFORE_ACQUIRE`
环境变量回退（`db.rs:83`、`:281`）。

**代价**：DB 重启/主从切换后的失效连接可能被首次借出并报错；sqlx 会在查询失败后重建连接，
因此表现为"单个请求失败"而非"连接池枯竭"。对账务类链路如需零抖动，显式置 1。

### 4. 日志：热路径读操作降为 `debug!`，默认级别回到 `info`

**问题**：`product/order/merchant/device` 的 list/info 每个请求 2 条 `info!`，实测 4.2k 行/s。
更关键的是 `main.rs` 默认过滤器是 `info,sz_rust_sz300=debug` —— **即使把日志降级为 `debug!` 也照样输出**，
降级本身不产生任何收益。

**决策**：
- 读路径 8 组日志降为 `debug!`（写路径 create/update/delete/bind/unbind 保持 `info!`）。
- 默认过滤器改回 `info`（`main.rs:20`），排障时用 `RUST_LOG=sz_rust_sz300=debug` 显式开启。
- `docker-compose.yml` 的 `RUST_LOG` 同步改为 `info`（k8s 已是 `warn,sz_rust_sz300=info`）。

**代价**：默认不再输出业务 debug 明细，排障需显式调整 `RUST_LOG`；日志采样/结构化字段未改。

### 5. 性能门禁 v2：可复现、可判定、接入 CI

**问题**（评测 §8 五项可核缺陷）：失败请求计入 QPS；分位数只统计成功样本；5 s 短跑比 60 s 稳态高估 1.34–1.41×；
门禁不发鉴权与 CSRF 双提交，业务端点永远 403；基线是跨机器占位值且无 workflow 引用。

**决策**（`scripts/perf-regression.js` 全量重写）：
- 口径：每端点预热 10 s → 稳态 60 s × 3 次，闭环；QPS 只计 2xx/3xx，错误率独立门禁（>0.5% 失败）；
  分位数覆盖全部已完成响应；多次重复取中位数并报 CV。
- 判据：QPS 中位数低于阈值 **且** ≥2 次重复同时低于阈值；有效阈值 = max(名义 5%, 3×CV)（上限 30%）——
  噪声大于阈值时不假装能判回归（评测实测 5% 固定阈值误报率 24.8%/41.4%）。
- 鉴权：现场签发 HS256（`--jwt-secret`）并补 CSRF 双提交（Cookie + `X-CSRF-TOKEN`），业务端点必须端到端 200。
- 基线：按环境指纹（CPU 型号/核数/内存/OS/Node 主版本）分槽（`schema=2`），换机器不再误判；
  仓库内**不保留任何占位数字**，`benches/baseline.json` 现为空指纹表。
- 安全：默认只允许回环地址，远端施压需显式 `--allow-non-loopback`。
- 退出码：0 PASS / 1 门禁失败 / 2 执行错误 / 3 当前指纹无基线。
- CI：新增 `.github/workflows/perf-gate.yml`（PR 仅做基线结构检查；手动/定时跑真实负载：
  MySQL 9.6 service → migrations 001–007 → `deploy/sql/perf-seed.sql` 确定性 2 万行 → release 构建 →
  启动 sz300 → 门禁）。**无基线时退出码 3 判定失败**并播种 artifact，提示人工提交，不产生"假绿"。

**代价**：单次门禁约 10 分钟负载，只能定时/手动触发；GitHub 托管 runner 指纹随镜像变化，
变化即视为"无基线"重新播种；限流器在 workflow 中被显式放大，因此**不覆盖**限流性能。

## 影响

- 行为变化：限流按对端 IP 分桶（同一 NAT 后的多客户端共享配额）；连接池不再每次探活；默认日志级别为 `info`。
- 默认值变化：`PoolConfig::test_before_acquire` true → false；`RUST_LOG` 兜底 `info,sz_rust_sz300=debug` → `info`。
- 门禁变化：`--skip-bench` 在无指纹基线时输出 `GATE INACTIVE` 并仍退出 0，但真实门禁（带服务）退出 3；
  旧文档中"`--skip-bench` = PASS 即代表性能达标"的表述已失效，不得再作为性能证据。
