# ADR-049：鉴权授权上下文缓存（LRU + TTL，替代每请求 merchant_user 查询）

> **状态**：已接受
> **日期**：2026-10-30
> **决策者**：SZ-Rust Team
> **相关代码**：`packages/sz-rust-sz300/src/services/auth_service.rs`、`packages/sz-rust-sz300/src/middleware/auth_middleware.rs`、`packages/sz-rust-sz300/src/query_cache.rs`、`packages/sz-rust-sz300/tests/auth_ctx_cache_test.rs`
> **关联 ADR**：[ADR-046](0046-性能工程整改-限流分桶与熔断窗口与门禁重写.md)（性能工程整改）、[ADR-048](0048-订单count查询缓存.md)（COUNT 查询缓存）

## 背景

31–60 天性能路线项「JWT claims 鉴权」旨在消除 `性能工程评测报告` §6 瓶颈 3 记录的第一条成本：**鉴权每请求查库**（`packages/sz-rust-sz300/src/middleware/auth_middleware.rs` 在 JWT 校验通过后调 `try_get_user_info_by_id`，对 `merchant_user` 做一次主键查询）。2026-10-28 IDOR 修复引入该查询，用于给业务控制器注入 `CurrentUser { merchant_id, is_admin }` 做数据归属过滤；此后**每一个**通过鉴权的业务请求都固定支付「1 次连接池获取 + 1 次 SQL 往返」，与业务本身无关。

路线原文写的是「把授权信息放进 JWT claims，鉴权不再查库」。实测前的两条约束使该做法风险过高：

- 访问令牌有效期在 `packages/sz-rust-sz300/src/main.rs:217` 硬编码为 `86400` 秒（24 h）。角色或商户归属一旦写进 claims，**撤销/降权最坏要 24 h 才生效**，且改角色必须等用户重新登录。
- `merchant_user.merchant_id` / `role` 由 DBA 或管理端 SQL 直接维护，应用内没有任何写路径可以顺带让旧令牌失效。

## 决策

1. **接口收窄**：`auth_service::try_get_user_info_by_id(user_id) -> Option<HashMap<String, Value>>` 改为
   `auth_service::auth_context(user_id) -> Option<AuthContext>`，其中
   `AuthContext { merchant_id: Option<i64>, is_admin: bool }`。
   SQL 投影同步收窄为 `SELECT u.merchant_id, u.role FROM merchant_user u WHERE u.user_id = ?`（参数化绑定，符合铁律「WHERE 必须参数化 + 禁止 `SELECT *`」）。`status`/`phone` 两列旧实现取而未用，本次不再查询；`/auth/me` 仍走未缓存的 `get_user_info_by_id`，返回完整档案。
2. **缓存载体**：复用 v1.9.0 `QueryCache`（LRU + TTL + 命中统计），进程级 `OnceLock<QueryCache>`，
   容量 **50,000 个用户**、TTL **60 s**，键 `auth:ctx:<user_id>`，值 = 定长 10 字节
   `[存在位 1B][merchant_id 8B LE][is_admin 1B]`。存在位区分「NULL」与「0」，不用哨兵值假设业务主键取值范围。
3. **只缓存正向结果**：查询失败、连接获取失败、用户不存在一律返回 `None` 且**不写缓存**，避免一次连接抖动被固化成 60 s 的降级。
4. **不做主动失效**：应用内唯一写 `merchant_user` 的路径是登录时更新 `last_login_at`（`auth_service.rs` 的 `UPDATE merchant_user SET last_login_at = NOW()`），不参与授权判断，因此没有需要即时失效的写路径。外部改 `role`/`merchant_id` 靠 TTL 自然过期。
5. **降级语义不变**：认证模块未初始化（测试环境）或 DB 不可用时仍返回 `None`，中间件按「无商户归属、非管理员」放行，与旧实现逐请求一致。
6. **观测**：`auth_service::auth_ctx_stats()` 暴露 `hits`/`misses`/`hit_rate`。**不接入 `/metrics`**——每请求做一次 registry 查找会把省下的开销以另一种形式加回来；命中率在集成测试与压测侧统计即可。

## 替代方案

| 方案 | 做法 | 未采纳理由 |
|------|------|-----------|
| A. 授权信息写进 JWT claims（路线原文） | 签发时把 `merchant_id`/`role` 写入 claims，中间件只验签不查库 | 撤销窗口 = 令牌有效期（`main.rs` 硬编码 86400 s），改角色需用户重新登录才生效；还要改签发端、`/auth/refresh` 与所有已发放令牌的兼容策略，协议面变更远大于收益 |
| B. 维持逐请求查库 | 不改 | 每个鉴权请求固定 1 次连接池获取 + 1 次 SQL 往返，是评测 §6 瓶颈 3 的第一条成本；连接池是全局共享资源，热点会传染到其他端点 |
| C. Redis / 共享缓存 | 授权上下文放外部缓存，多实例共享 | 引入新的运行时依赖与网络往返（回环内一次 Redis RTT 与一次 MySQL 主键查询同量级，收益不成立）；当前部署形态是单实例，`TOKEN_BLACKLIST` 也已是进程内方案，保持同一口径 |
| D. **进程内 LRU + TTL（本决策）** | 命中即免查库，TTL 60 s 兜底外部变更 | — |

## 后果

### 正面后果

- 缓存命中后，业务请求的 SQL 往返从「鉴权 1 次 + 业务 N 次」降为「业务 N 次」。同一用户 60 s 窗口内的全部请求不再占用连接池，池等待与上下文切换随之下降；对 `order/list`（COUNT 已由 ADR-048 缓存）而言，稳态下每请求只剩 1 次列表查询。
- 相比原路线的「claims 方案」，授权陈旧窗口从 **最坏 24 h（令牌有效期）压缩到 ≤60 s**，且不需要改令牌协议、不需要用户重新登录。
- 内存开销可忽略：50,000 × 10 B ≈ 0.5 MB（另含 LRU 索引与键字符串）。

### 负面后果

- **授权属性最多 60 s 最终一致**：外部直接改 `role`（管理员降权）或 `merchant_id`（商户迁移）后，最长 60 s 内旧属性仍生效；单实例部署有效，多实例各自持有独立缓存（陈旧窗口仍是 ≤60 s，不叠加）。
- 缓存的是「中间件注入的归属过滤依据」，不是「能不能访问」——令牌吊销仍由 `verify_token` 内的 `TOKEN_BLACKLIST` 每次请求检查，`logout` 依旧即时生效。
- 用户数超过 50,000 时 LRU 逐出最久未用条目，被逐出用户的下一次请求回源（正确性不受影响，只影响命中率）。

## 注意事项

- 若未来给 `merchant_user` 增加**应用内**角色写路径（管理后台改角色），必须在该写路径提交成功后调用 `auth_ctx_cache().invalidate("auth:ctx:<user_id>")`，否则 60 s 窗口内会按旧角色授权。当前 `QueryCache::invalidate` 已具备单键失效能力。
- 若需要「改角色立即生效」，正确做法是缩短 TTL 或引入失效广播（Redis pub/sub），不要退回逐请求查库。
- 进程级静态缓存与进程级 `DB_POOL` 使集成测试对「运行时生命周期」敏感：四个场景必须合并到同一个 `#[tokio::test]` 内串行执行。拆成多个 `#[tokio::test]` 时，首个用例结束会关闭其创建连接池所用的运行时，后续用例复用 `DB_POOL` 会拿到死池并把结果误判为「用户不存在」（2026-10-30 真库复现并修正）。

## Bug 定位提示

- 某用户被判定为「其他商户」或「非管理员」而 DB 已是新值：先确认是否在 60 s TTL 窗口内（`auth_ctx_stats()` 的 hits 是否在该 user_id 上持续增长），再核对 `encode_auth_ctx`/`decode_auth_ctx` 的字节布局。
- 命中率长期为 0：检查 `DB_POOL` 是否已初始化（未初始化时 `auth_context` 直接返回 `None`，不写缓存），或 `merchant_user` 查询是否因连接错误静默降级。
- 关键代码路径：`packages/sz-rust-sz300/src/services/auth_service.rs`（`AuthContext` / `auth_ctx_cache` / `auth_context`）、
  `packages/sz-rust-sz300/src/middleware/auth_middleware.rs`（`run_with_user_context`）、
  `packages/sz-rust-sz300/tests/auth_ctx_cache_test.rs`（真库四组场景：命中/回源/删行后仍命中/负结果不缓存）。
