# SzRSQL 数据库兼容性评估报告

> **版本**: v1.0 (2026-07-24)
> **评估方法**: 基于 `szrsql-pgcompat` 测试套件实测 + 源码审查 + 方言解析器验证
> **评估对象**: SzRSQL v0.1.0

---

## 1. 总览

| 数据库 | 兼容等级 | 通过率 | 关键限制 |
|--------|---------|--------|---------|
| **PostgreSQL** | L2（协议级兼容） | 89.6% (95/106) | 5 项语法不支持、5 项数据类型未实现 |
| **MySQL** | L1（方言解析） | ~70%（估算） | 仅文本级预处理，无存储引擎兼容 |
| **SQLite** | L0（语法借鉴） | N/A | 无方言支持，仅 FTS5 风格全文检索借鉴 |
| **Oracle** | L1（方言解析） | ~60%（估算） | 仅文本级预处理（ROWNUM/DECODE/NVL） |
| **SQL Server** | L1（方言解析） | ~65%（估算） | 仅文本级预处理（TOP/ISNULL/GETDATE） |

**兼容等级定义**:
- L0：语法借鉴（无实际兼容性）
- L1：方言解析（能解析 SQL，但语义/行为可能不一致）
- L2：协议级兼容（客户端驱动可直接连接）
- L3：行为级兼容（SQL 语义、错误码、数据类型完全一致）

## 2. PostgreSQL 兼容性（实测）

### 2.1 实测数据（cargo run -p szrsql-pgcompat --example print_report）

```
总检查项: 106
通过(含部分): 95 (89.6%)
完全通过: 95 (89.6%)

分类统计:
- SQL 语法: 54 项 (通过 48, 88.9%)
- SQLSTATE: 16 项 (通过 16, 100%)
- 数据类型: 28 项 (通过 23, 82.1%)
- 协议合规: 8 项 (通过 8, 100%)
```

### 2.2 不通过项明细（11 项）

#### SQL 语法失败（6 项）

| 失败项 | 原因 | 影响 |
|--------|------|------|
| SUBSTRING 函数 | `unsupported expr: Substring` | 字符串截取不可用 |
| UUID 类型（语法层） | `invalid data type: Uuid` | DDL 中不能直接使用 UUID 类型 |
| ILIKE 运算符 | `unsupported expr: ILike` | 大小写不敏感 LIKE 不可用 |
| SIMILAR TO 运算符 | `unsupported expr: SimilarTo` | 正则模式匹配不可用 |
| IS DISTINCT FROM | `unsupported expr: IsDistinctFrom` | NULL 安全不等比较不可用 |
| ~ 正则匹配运算符 | 未测试（预计失败） | PG 特有正则运算符 |

#### 数据类型未实现（5 项）

| 未实现类型 | 状态 | 替代方案 |
|-----------|------|---------|
| `interval` | NOT_IMPLEMENTED | 无（时间间隔不可用） |
| `bit` / `varbit` | NOT_IMPLEMENTED | 无（位串不可用） |
| `cidr` / `inet` | NOT_IMPLEMENTED | 存为 Text |
| `point` / 几何类型 | NOT_IMPLEMENTED | 无（PostGIS 不可用） |
| `xml` | NOT_IMPLEMENTED | 存为 Text |

### 2.3 通过项亮点

- **SQLSTATE 100% 一致**：16 个核心错误码与 PG 官方完全一致
- **协议合规 100%**：pgwire v3.0、SCRAM-SHA-256、Severity 全部一致
- **核心 DML 完整**：SELECT/INSERT/UPDATE/DELETE/JOIN/GROUP BY/HAVING/ORDER BY/LIMIT/OFFSET 全部通过
- **核心 DDL 完整**：CREATE TABLE/INDEX/VIEW、DROP、ALTER 全部通过
- **核心数据类型**：bigint/integer/text/timestamp/numeric/json/bytea/boolean/array/enum 全部支持

## 3. MySQL 兼容性

### 3.1 支持范围

SzRSQL 通过 `dialect.rs` 的文本级预处理支持部分 MySQL 语法：

| MySQL 语法 | 支持状态 | 转换策略 |
|-----------|---------|---------|
| `LIMIT offset, count` | ✅ 支持 | 预处理为 `LIMIT count OFFSET offset` |
| `REPLACE INTO` | ✅ 支持 | MySQL 扩展，直接解析 |
| `SET NAMES 'charset'` | ✅ 支持 | MySQL 语法，直接解析 |
| 反引号标识符 `` `id` `` | ✅ 支持 | MySqlDialect 原生支持 |
| `AUTO_INCREMENT` | ❌ 不支持 | 需用 SERIAL/BIGSERIAL |
| `UNSIGNED` 类型修饰 | ❌ 不支持 | 需移除 |
| `ENGINE=InnoDB` | ❌ 不支持 | 需移除 |
| `ON DUPLICATE KEY UPDATE` | ❌ 不支持 | 需改用 `ON CONFLICT` |
| `LOCK IN SHARE MODE` | ❌ 不支持 | 无兼容方案 |
| `SQL_CALC_FOUND_ROWS` | ❌ 不支持 | 需改用 `COUNT(*)` |

### 3.2 兼容性评估

- **通过率估算**：~70%（核心 DML 可用，DDL 需改写）
- **主要限制**：
  - 文本级预处理，不解析 SQL 语义，复杂嵌套场景可能失效
  - 无 MySQL 协议支持（不能通过 MySQL 驱动连接）
  - 存储引擎不兼容（无 InnoDB 行格式、无索引组织表）
- **适用场景**：MySQL SQL 迁移到 SzRSQL 时可部分自动转换

## 4. SQLite 兼容性

### 4.1 支持范围

SzRSQL **不提供** SQLite 方言支持。`Dialect::from_str("sqlite")` 返回错误。

| SQLite 特性 | 支持状态 | 说明 |
|------------|---------|------|
| FTS5 全文检索 | ✅ 借鉴 | `szrsql-sql/src/extended_index.rs` 实现 SQLite 风格 FTS5 |
| `CREATE VIEW IF NOT EXISTS` | ✅ 支持 | SQLite/BigQuery 方言特性 |
| SQLite 方言解析 | ❌ 不支持 | 无 `Dialect::Sqlite` |
| SQLite 文件格式 | ❌ 不支持 | 无 `.db` 文件读写 |
| SQLite C API | ❌ 不支持 | 无 libsqlite3 兼容 |

### 4.2 兼容性评估

- **兼容等级**：L0（仅语法借鉴）
- **通过率**：N/A（无方言解析支持）
- **适用场景**：FTS5 全文检索语法可互通，其余不兼容

## 5. 其他数据库兼容性

### 5.1 Oracle（方言解析 L1）

| Oracle 语法 | 支持状态 | 转换策略 |
|------------|---------|---------|
| `ROWNUM <= N` | ✅ 支持 | 预处理为 `LIMIT N` |
| `DECODE(...)` | ✅ 支持（简单） | 预处理为 `CASE WHEN` |
| `NVL(a, b)` | ✅ 支持 | 预处理为 `COALESCE(a, b)` |
| `TO_DATE(s, fmt)` | ✅ 支持 | 预处理为 `CAST(s AS TIMESTAMP)` |
| `seq.NEXTVAL` | ✅ 支持 | 预处理为 `nextval('seq')` |
| `SYSDATE` | ✅ 支持 | 预处理为 `CURRENT_TIMESTAMP` |
| PL/SQL 存储过程 | ❌ 不支持 | 无 PL/SQL 引擎 |
| Oracle 协议 | ❌ 不支持 | 无 OCI 协议 |

### 5.2 SQL Server（方言解析 L1）

| T-SQL 语法 | 支持状态 | 转换策略 |
|-----------|---------|---------|
| `SELECT TOP N` | ✅ 支持 | 预处理为 `LIMIT N` |
| `ISNULL(a, b)` | ✅ 支持 | 预处理为 `COALESCE(a, b)` |
| `GETDATE()` | ✅ 支持 | 预处理为 `CURRENT_TIMESTAMP` |
| `T-SQL 存储过程` | ❌ 不支持 | 无 T-SQL 引擎 |
| TDS 协议 | ❌ 不支持 | 无 TDS 协议 |

## 6. 兼容性改进路线图

### 6.1 短期（v0.2.0）— PostgreSQL 语法补全

| 优先级 | 改进项 | 预计工作量 |
|--------|--------|-----------|
| P0 | SUBSTRING 函数支持 | 小（parser 扩展） |
| P0 | IS DISTINCT FROM 支持 | 小（parser 扩展） |
| P1 | ILIKE 运算符支持 | 小（parser + executor） |
| P1 | UUID 类型支持 | 中（类型系统扩展） |
| P2 | SIMILAR TO 运算符 | 中（正则引擎集成） |
| P2 | ~ 正则匹配运算符 | 中（同上） |

### 6.2 中期（v0.3.0）— PostgreSQL 数据类型补全

| 优先级 | 改进项 | 预计工作量 |
|--------|--------|-----------|
| P1 | interval 类型 | 中（类型系统 + 运算） |
| P1 | bit/varbit 类型 | 小（类型系统） |
| P2 | cidr/inet 网络类型 | 中（类型系统 + 运算） |
| P3 | PostGIS 几何类型 | 大（需独立 crate） |
| P3 | xml 类型 | 中（类型系统 + 解析） |

### 6.3 长期（v0.4.0+）— 协议级兼容

| 改进项 | 说明 |
|--------|------|
| MySQL 协议支持 | 实现 MySQL Wire Protocol，允许 MySQL 驱动直连 |
| SQLite 存储引擎 | 实现 SQLite 文件格式兼容（作为存储后端选项） |

---

## 7. 结论

SzRSQL 当前以 PostgreSQL 兼容为主方向，达到 **L2 协议级兼容**（89.6% 通过率），核心 SQL 语法和数据类型基本可用，但缺少 5 项高级语法和 5 项数据类型。

对 MySQL/Oracle/SQL Server 提供 **L1 方言解析**（文本级预处理），可用于 SQL 迁移但非协议级兼容。

对 SQLite **无兼容性**（L0），仅 FTS5 语法借鉴。

**建议**：v0.2.0 优先补全 PostgreSQL 的 6 项语法失败项，将达到 95%+ 兼容性，满足大多数 PG 应用迁移需求。
