# 审计质量规范（sz-rust framework）

## 🚫 审计前强制清单（未全部完成则禁止开始审计）

> 以下清单为**硬闸门**，必须逐项执行并输出结果，不得跳过或声称"已知晓"。

- [ ] **运行基线测试**：执行 `cargo test -p sz-rust-core --lib` 并记录输出中的 `test result: ok. N passed; 0 failed`
- [ ] **确认编译通过**：执行 `cargo check --workspace` 并确认无 error
- [ ] **记录基线测试数 N**：将 N 写入审计报告开头，作为后续对比基准
- [ ] **声明审计范围**：明确本次审计覆盖的模块列表（如 `src/middleware/`, `src/cache.rs`）

> ⚠️ 违反上述任意一项，审计结果视为无效，必须重新执行。

## 核心原则

> **每项修复、优化、更新后必须实际运行相关测试套件验证，不更新文档状态，除非测试真实通过，执行时主动扫描同类问题，所有结论附 file:line 证据。**

## 🔒 单一审计流程（禁止并行 Agent 审计）

> 审计必须**顺序执行**，禁止使用多个并行 Agent 分别扫描同一代码库。
> 原因：并行 Agent 无法共享上下文，导致结论矛盾、重复扫描、证据无法交叉验证。

- ✅ 正确：单一 Agent 顺序执行每个检查项，每步输出 file:line 证据
- ❌ 错误：启动 6 个 Agent 各自扫描，最后合并结论（无法验证一致性）

## 审计流程

### 1. 审计前准备

- [ ] 确认当前测试套件状态：`cargo test -p sz-rust-core --lib`
- [ ] 记录当前测试数量：`test result: ok. N passed; 0 failed`
- [ ] 确认编译通过：`cargo check --workspace`

### 2. 审计执行

- [ ] **每项修复必须附带测试证据**
  - 修复前：记录失败测试（如有）
  - 修复后：**立即**运行相关测试套件（不得延迟到审计结束后批量运行）
  - 证据格式：`cargo test -p sz-rust-core --lib <module>:: -- --test-threads=1`
  - 输出：`test result: ok. N passed; 0 failed`
  - ⚠️ 修复后测试数必须 ≥ 修复前基线数 N；若下降，必须说明原因

- [ ] **所有结论必须附带 file:line 证据**
  - 正确示例：`[src/middleware/auth.rs:127-143](file:///.../auth.rs#L127-L143) 已修复 JWT 签发人校验`
  - 错误示例：`已修复 auth 模块的 JWT 问题`（无证据）
  - ⚠️ 证据中的文件路径和行号必须真实存在，不得编造

- [ ] **主动扫描同类问题**
  - 修复一处后，搜索整个代码库是否有同类问题
  - 示例：修复 `unwrap()` 后，搜索 `Grep(pattern="unwrap\\(\\)", path="src")`
  - 报告所有发现，不遗漏

- [ ] **每项结论独立验证**
  - 禁止结论之间互相引用（如"见结论 3"）
  - 每条结论必须独立附带完整的 file:line + 测试证据

### 3. 文档更新

- [ ] **测试未通过前，禁止更新文档状态**
  - ❌ 错误：先更新文档标记 ✅，再运行测试
  - ✅ 正确：先运行测试通过，再更新文档

- [ ] **文档更新必须附带测试证据**
  - 示例：`| Slack 通知 | ✅ | `sz-rust-core::notify` | 2026-07-31 完成，43 个单元测试全部通过 |`

### 4. 审计结论

- [ ] **禁止互相引用文档**
  - ❌ 错误：`参见审计报告.md 第 3 节`
  - ✅ 正确：直接引用代码位置 `src/middleware/auth.rs:127`

- [ ] **禁止未经验证的结论**
  - ❌ 错误：`性能应该没问题`
  - ✅ 正确：`性能测试通过：QPS=12000, P99=2.3ms（见 benchmarks/load_test.rs）`

### 5. 审计后验证（硬闸门，未通过则审计报告无效）

- [ ] **运行审计验证脚本**：
  ```bash
  bash .trae/scripts/audit-verify.sh <审计报告.md>
  ```
  脚本会逐项验证报告中所有 file:line 引用是否真实存在于代码中。
- [ ] **确认测试数未下降**：最终 `cargo test -p sz-rust-core --lib` 的 passed 数 ≥ 审计前基线数
- [ ] **填写审计质量自查表**（见下方模板），不得留空

## 审计证据清单

### 必须提供的证据

| 证据类型 | 格式 | 示例 |
|---------|------|------|
| 测试通过 | `cargo test` 输出 | `test result: ok. 43 passed; 0 failed` |
| 编译通过 | `cargo check` 输出 | `Finished dev [unoptimized + debuginfo] target(s)` |
| 代码位置 | `file:line` 链接 | `[src/middleware/auth.rs:127](file:///.../auth.rs#L127)` |
| 性能基线 | 测试报告 | `QPS=12000, P99=2.3ms` |
| 安全扫描 | 扫描结果 | `cargo audit: 0 vulnerabilities` |

### 禁止的证据形式

| 形式 | 原因 |
|------|------|
| `应该没问题` | 未验证 |
| `参见其他文档` | 互相引用 |
| `大概/可能/也许` | 不确定 |
| `已修复`（无测试） | 无证据 |

## 违规处理

发现以下违规行为，必须立即停止审计，报告用户：

1. **测试未通过但文档标记为 ✅**
2. **结论无 file:line 证据**
3. **互相引用文档，无直接代码证据**
4. **未运行测试即声称"已修复"**
5. **使用并行 Agent 分别扫描同一代码库**（结论无法交叉验证）
6. **审计前强制清单未完成即开始审计**
7. **审计后未运行 audit-verify.sh 验证脚本**
8. **file:line 证据中的行号超出文件实际行数**（编造证据）
